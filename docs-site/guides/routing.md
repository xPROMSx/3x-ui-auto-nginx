# Маршрутизация в 3x-ui: выбираем, куда отправлять трафик

**Создано:** 23 ноября 2026 года.

**Актуально для:** 3X-UI AUTO NGINX **v2.8.0**, панели **3x-ui v3.11.0** и Xray **26.10.21**. Примеры основаны на панели и правилах каскада этих версий.

## Зачем нужна маршрутизация и чему ты научишься

Когда телефон подключается к твоему VPS, это ещё не определяет, **через какой сервер запрос уйдёт к сайту**. Входящее подключение (inbound) принимает трафик от устройства. Исходящее (outbound) либо выпускает его непосредственно в интернет, либо отправляет дальше, например на другой VPS. **Правило маршрутизации** выбирает нужный выход.

``` { .text .no-copy }
Телефон → входящее REALITY/XHTTP на VPS → правила Xray
                                            ├─ direct → Интернет с этого VPS
                                            ├─ blocked → запрос заблокирован
                                            └─ backup-se → Второй VPS → Интернет
```

В этой инструкции ты разберёшь готовые правила нашего каскада и сможешь перейти сразу к нужному примеру:

- [Только YouTube через второй сервер](#route-youtube).
- [Весь обычный трафик через выбранный сервер](#route-all).
- [Заблокировать российские ресурсы одному клиенту](#route-block-client).
- [Отправить входящее XHTTP через второй сервер](#route-xhttp).

Если впервые настраиваешь маршруты, сначала прочитай [как работает приоритет правил](#route-priority).

Примеры ниже самостоятельны. Для примеров с `backup-se` сначала [добавь исходящее подключение](import-reality.md) и проверь его через HTTP. Для изменения `CASCADE - EXIT` нужен уже настроенный [каскад](cascade.md). Все теги ниже - примеры: в своей панели выбирай существующие значения.

## 1. Как наш каскад направляет трафик по умолчанию

При подключении каскада через менеджер 3X-UI AUTO NGINX на **входном сервере** автоматически появляются исходящий `cascade-exit` и три правила в разделе **Xray → Маршрутизация → Маршрутизация**:

| Правило | Что совпадает | Куда отправляется |
| --- | --- | --- |
| `CASCADE - RU` | Домены `geosite:category-ru` | `direct` |
| `CASCADE - RU2` | IP назначения `geoip:ru` | `direct` |
| `CASCADE - EXIT` | TCP и UDP, если предыдущие правила не сработали | `cascade-exit` |

**Почему сделано именно так?** Российские ресурсы обычно можно открывать с российского входного VPS непосредственно, не отправляя запрос в Европу и обратно. Так уменьшается лишний маршрут и сохраняется выход с российского IP для подходящих ресурсов. Остальной подходящий трафик идёт на зарубежный VPS. Это правило по умолчанию, а не запрет на собственные настройки.

``` { .text .no-copy }
Запрос к российскому домену/IP → CASCADE - RU / RU2 → direct
Остальной подходящий запрос      → CASCADE - EXIT     → зарубежный VPS
```

`geosite:category-ru` и `geoip:ru` - наборы доменов и IP-диапазонов в геобазах Xray. Они не знают гражданство сайта и не охватывают безошибочно все ресурсы. Важен фактический домен или IP назначения и наличие подходящих данных для сопоставления.

!!! info "Обычный маршрут каскада - не буквально весь интернет через Европу"
    Российские исключения находятся **выше** `CASCADE - EXIT`, поэтому подходят первыми. Кроме того, раньше могут стоять служебные правила панели и твои собственные правила. Не удаляй служебные правила для `api` и внутренних адресов.

## 2. Приоритет правил: первое совпадение выигрывает {#route-priority}

Xray рассматривает **включённые правила сверху вниз**. Как только условия какого-то правила совпали, выбирается указанный там выход или балансировщик; ниже расположенные правила для этого соединения уже не применяются.

- **Разные типы условий в одном правиле** (например, «Пользователь» и «Домен») должны выполниться одновременно. Так удобно ограничить правило одним клиентом.
- **Несколько значений одного поля** (например, два домена) позволяют совпасть с любым подходящим значением.
- **Точечные правила располагай выше общих**: правило для YouTube - над `CASCADE - EXIT`; блокировку для одного пользователя - над общими `CASCADE - RU` и `CASCADE - RU2`.
- Если правило вообще не совпало, Xray использует свой маршрут по умолчанию. Не полагайся на это случайно: порядок исходящих в конфигурации тоже имеет значение.

На странице **Xray → Маршрутизация** открой вкладку **«Маршрутизация»** со списком правил. Кнопка добавления находится над таблицей; значок карандаша редактирует существующее правило. Порядок можно менять перетаскиванием или командами перемещения. После правок нажми **«Сохранить»** на основной странице Xray.

Для проверки нового правила удобно воспользоваться соседней вкладкой **тестирования маршрута** и дополнительно проверить настоящий запрос с подключённого устройства. Тест выбора маршрута и проверка выходного IP отвечают на разные вопросы.

!!! warning "Не забывай сохранять действующую конфигурацию"
    Перед изменением маршрутизации сделай [резервную копию настроек](backup.md). Новый маршрут может временно прервать соединения. Если результат оказался неожиданным, верни прежнее значение или отключи созданное правило и снова сохрани Xray.

## 3. Пример: только YouTube через второй сервер {#route-youtube}

**Результат:** YouTube отправляется через `backup-se`, а остальные сайты сохраняют прежние маршруты. Нужен работающий исходящий `backup-se`; готовый каскад необязателен.

Значение для поля «Домен» (можно скопировать кнопкой):

```text
geosite:youtube
```

1. Убедись, что исходящий `backup-se` существует и успешно проходит [HTTP-тест](import-reality.md#http-test).
2. Открой на **входном VPS** раздел **Xray → Маршрутизация**, вкладку со списком правил.
3. Нажми кнопку добавления правила.
4. В поле «Комментарий» введи `YouTube via backup`.
5. В поле «Домен» вставь `geosite:youtube` из блока выше. Это набор доменов YouTube и сопутствующих ресурсов, а не один адрес `youtube.com`.
6. В поле **«Тег исходящего» (outboundTag)** выбери `backup-se`. **«Тег балансировщика»** не заполняй.
7. Оставь остальные условия пустыми, включи правило и создай его.
8. Перемести правило выше общих правил, которые могут перехватить запрос. Если настроен каскад, поставь его выше `CASCADE - RU`, `CASCADE - RU2` и `CASCADE - EXIT`. Служебные правила не удаляй.
9. Нажми общее **«Сохранить»** для Xray.

Проверь маршрут для имени вроде `www.youtube.com` и затем открой видео через устройство, подключённое к входному VPS. Для сопоставления доменов Xray должен получать доменное имя: оно может поступать из прокси-запроса или через sniffing (определение домена по данным соединения), если функция включена. Когда приложение обращается только по IP и Xray не знает домен, правило `geosite` может не сработать.

**Откат:** выключи или удали только `YouTube via backup`, сохрани конфигурацию.

## 4. Пример: весь обычный трафик через выбранный сервер {#route-all}

**Результат:** трафик пользовательских соединений, который не перехватывают более ранние служебные или специальные правила, уходит через `backup-se`.

Этот пример рассчитан на работающий каскад с правилом `CASCADE - EXIT` и проверенным исходящим `backup-se`. Не создавай второе широкое правило. Используй существующее:

1. Открой **Xray → Маршрутизация → Маршрутизация** на входном VPS.
2. Найди `CASCADE - EXIT`. Запомни его текущий исходящий тег и состояние переключателей `CASCADE - RU` и `CASCADE - RU2`, чтобы при необходимости вернуть их. Нажми карандаш.
3. Измени **«Тег исходящего»** с `cascade-exit` на `backup-se`. Балансировщик оставь пустым.
4. Сохрани правило.
5. Если нужен выход через `backup-se` также для российских сайтов, **отключи** `CASCADE - RU` и `CASCADE - RU2` переключателями. Это может нарушить доступ к сайтам, которым нужен российский IP. Если хочешь сохранить прежние российские исключения, не меняй их состояние.
6. Нажми общее **«Сохранить»**.

Таким образом ты перенаправляешь общий маршрут, но не меняешь входящие профили и клиентов. Отключение двух российских правил затронет и российские ресурсы, поэтому сайты, которым нужен российский IP, могут перестать открываться как прежде.

**Не удаляй `cascade-exit`, служебные правила Xray или клиента `cascade` на зарубежном VPS:** они принадлежат действующей конфигурации каскада. Менеджер каскада может по-прежнему считать входную роль настроенной. Перед последующим отключением каскада через менеджер проверь пользовательские маршруты и зависимости.

**Проверка:** через устройство, действительно использующее входной VPS, открой страницу проверки IP. При прямом выходе с `backup-se` она должна показать публичный IP второго сервера (если там нет дополнительного WARP/прокси). Для каждого проверяемого сайта учитывай правила выше `CASCADE - EXIT`.

**Откат:** верни в `CASCADE - EXIT` прежний исходящий тег и исходное состояние переключателей `CASCADE - RU` и `CASCADE - RU2`, сохрани.

## 5. Пример: заблокировать российские ресурсы одному клиенту {#route-block-client}

**Результат:** для выбранного клиента российские домены и IP блокируются, а остальные клиенты продолжают работать по прежним правилам. Каскад и второй VPS необязательны. Если каскада нет, размести новые правила выше общих правил, которые могли бы обработать этот трафик.

Здесь понадобится **email клиента внутри 3x-ui** (идентификатор пользователя для правил Xray), а не логин от веб-панели. Допустим, email клиента - `example-client`.

Создай **два отдельных правила** и размести их выше общих маршрутов (в каскаде - выше `CASCADE - RU`, `CASCADE - RU2` и `CASCADE - EXIT`):

| Поле | Правило 1 | Правило 2 |
| --- | --- | --- |
| Комментарий | `Block RU domains for client` | `Block RU IP for client` |
| Пользователь (user) | `example-client` | `example-client` |
| Домен | `geosite:category-ru` | оставить пустым |
| IP | оставить пустым | `geoip:ru` |
| Тег исходящего | `blocked` | `blocked` |

1. Открой **Xray → Маршрутизация → Маршрутизация** на VPS, к которому подключается этот клиент, и нажми добавление правила.
2. Выбери нужного клиента в поле **«Пользователь»** (панель может показывать список email).
3. Заполни поля по колонке «Правило 1», оставь остальные условия пустыми, включи и создай правило.
4. Создай второе правило по колонке «Правило 2», снова выбрав того же пользователя и выход `blocked`.
5. Перемести оба правила выше общих правил каскада (или других общих правил, если каскада нет), не удаляя служебные правила, и нажми общее **«Сохранить»**.

Почему два правила? Если заполнить одновременно `domain` и `ip` в одном, Xray будет искать соединение, удовлетворяющее **обоим** условиям. Два правила покрывают разные случаи. Блокировка по геобазам не является полным блокированием всех сайтов, связанных с Россией: домены могут отсутствовать в списке или разрешаться в зарубежные IP.

**Проверка:** открой подходящий ресурс через профиль `example-client`, затем повтори другим клиентом. Второй клиент не должен попасть под эти ограничения. Если правило неожиданно действует на всех, проверь, что поле «Пользователь» не осталось пустым.

**Откат:** выключи оба добавленных правила, сохрани Xray.

## 6. Пример: отправить входящее XHTTP через второй сервер {#route-xhttp}

**Результат:** подключения, пришедшие через выбранное **входящее XHTTP**, уходят через `backup-se`, а остальные входящие REALITY и Hysteria2 сохраняют свои маршруты. Нужны отдельное входящее XHTTP и проверенный исходящий `backup-se`; готовый каскад необязателен.

**Осторожно с несколькими транспортами:** `inboundTag` различает входящие подключения, а не всегда отдельные транспорты одного входящего. Если одно входящее объединяет несколько способов приёма трафика, правило затронет **всё это входящее**, а не только XHTTP. Сначала проверь, что тег действительно принадлежит нужному отдельному входящему.

1. Перейди на входном VPS в раздел **Входящие** и открой настройки нужного подключения **VLESS XHTTP**.
2. Узнай и точно скопируй его **тег входящего (inboundTag)**. Не путай тег с названием клиента, портом или полем `network`.
3. Открой **Xray → Маршрутизация → Маршрутизация** и создай правило.
4. В поле «Комментарий» напиши `XHTTP via backup`.
5. В поле **«Теги входящих» (inboundTag)** выбери найденный тег XHTTP.
6. В поле **«Тег исходящего»** выбери `backup-se`. Остальные условия оставь пустыми.
7. Перемести правило **выше общих маршрутов**, которые могли бы перехватить трафик XHTTP, включая правила каскада, если он настроен. Включи правило и нажми общее «Сохранить».

**Проверка:** подключись с устройства через профиль XHTTP и проверь внешний IP. Затем повтори через другое входящее подключение. Второе должно сохранить исходный маршрут, если другие правила его не меняют.

**Откат:** отключи правило `XHTTP via backup` и сохрани Xray.

## На что ещё влияет маршрутизация

- **Порядок важнее имени правила.** Комментарии служат для удобства человека; Xray выбирает по условиям и порядку.
- **`direct` и `blocked` - тоже исходящие.** Первое выпускает трафик непосредственно с текущего VPS, второе отклоняет его.
- **Доменные правила зависят от того, знает ли Xray домен.** Результат может отличаться, когда приложение передаёт уже готовый IP.
- **Сервисные правила не трогай.** В частности, правило для `api` нужно панели, а блокировка частных IP предотвращает нежелательные подключения к внутренним адресам.
- **После подключения каскада новые правила следует ставить осознанно.** Управляемый `CASCADE - EXIT` работает как общее правило, поэтому более узкие исключения размещают над ним.

Если требуется не вручную выбирать один выход, а **автоматически переключаться на запасной VPS при отказе основного**, переходи к [руководству по балансировщику](balancer.md). Там существующее правило `CASCADE - EXIT` будет использовать тег балансировщика вместо прямого исходящего тега.
