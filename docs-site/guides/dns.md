# Личный DNS и AdGuard Home

## Для чего нужен свой DNS-сервер

DNS (система доменных имён) переводит название сайта в IP-адрес. Обычно устройство отправляет такие запросы DNS-провайдеру сети. С помощью **AdGuard Home** ты можешь управлять ими на собственном VPS: видеть обращения устройств, блокировать домены рекламы и отслеживания, создавать свои правила и выбирать вышестоящие DNS-серверы.

3X-UI AUTO NGINX устанавливает и связывает AdGuard Home с уже работающим nginx. Твой DNS получает защищённый HTTPS-адрес на домене панели, а управление доступно через отдельную веб-панель. Никакого дополнительного домена не требуется.

### Две разные DNS-функции установщика

| Функция | Для кого работает | Когда включается |
| --- | --- | --- |
| **Шифрованный DNS самого VPS** | Глобальные DNS-запросы сервера через systemd-resolved | При выборе «Расширенная безопасность VPS» |
| **AdGuard Home** | Телефоны, компьютеры и другие устройства, которые ты к нему подключишь | По отдельному вопросу установщика |

Первая функция защищает глобальные DNS-запросы самого VPS. Вторая даёт личный DNS с фильтрацией и журналом запросов. Установка AdGuard Home сама по себе не переключает на него DNS VPS, Xray или клиентских приложений. Чтобы пользоваться фильтрацией на телефоне или компьютере, настрой личный DNS на устройстве или в приложении.

**Выбери способ подключения:**

- [Часть 1. DoH (рекомендуем)](#device-doh) - подключение по персональному HTTPS-адресу, ClientID по желанию.
- [Часть 2. DoT (частный DNS Android)](#device-dot) - системная настройка Android по имени домена.
- [Использовать DoH и DoT одновременно](#dns-both) - особенности общего списка разрешённых клиентов.

Если 3X-UI AUTO NGINX уже установлен без AdGuard Home, не выбирай повторную «Установку» только ради DNS: она заменяет управляемые данные. Штатного отдельного пункта добавления AdGuard Home в действующий стек нет. Если решишь развернуть проект заново, заранее сохрани [Backup вне VPS](backup.md).

## Часть 1. Подключение через DoH {#device-doh}

Этот вариант подходит для устройств и приложений с поддержкой DNS-over-HTTPS. Можно различать устройства и разрешать запросы только своим клиентам.

### Шаг 1. Получи адрес DoH

Если VPS новый, пройди [первый запуск](../start.md). На вопрос «Установить и настроить AdGuard Home?» ответь Y, а на вопрос «Включить DNS-over-TLS (DoT) для ваших устройств?» - N, если DoT не нужен.

После установки сохрани адрес панели AdGuard Home, логин и пароль. В уже установленном проекте адреса можно посмотреть в меню **«6. Данные моего сервера»**, если AdGuard Home включён.

Примеры адресов (не копируй буквально):

- Панель: `https://panel.example.com/adg-.../`
- DoH: `https://panel.example.com/dns-XXXXXXXXXXXX`

Порт 53 проект наружу не открывает. Для DoH используется nginx и существующий HTTPS-домен панели. Открой адрес панели AdGuard Home и войди.

### Шаг 2. При желании настрой ClientID {#doh-clientid}

В новых установках DoH уже имеет индивидуальный случайный путь вида `/dns-XXXXXXXXXXXX`. Для обычного личного использования достаточно этого адреса, если список разрешённых клиентов не настроен. Не публикуй его: случайный путь затрудняет подбор, но не является полноценной аутентификацией.

**ClientID** - идентификатор устройства, который добавляется к DoH-адресу. Он полезен, если нужно различать устройства в журнале, назначать им отдельные правила или ограничить доступ списком разрешённых клиентов. Особенно рекомендуем ClientID для старых установок с общим предсказуемым путём `/dns-query`.

Если ClientID не нужен и список разрешённых клиентов пуст, сразу переходи к шагу 3.

!!! warning "Если одновременно используешь DoT"
    До сохранения списка разрешённых клиентов добавь в него также `127.0.0.1`, иначе DoT перестанет отвечать. Это разрешит публичные запросы DoT. Если используешь только DoH, локальный адрес добавлять не нужно.

1. В AdGuard Home создай постоянного клиента для каждого устройства и назначь ему длинный индивидуальный ClientID.
2. Перейди в **Настройки → Настройки DNS → Настройки доступа → Разрешённые клиенты**.
3. Добавь нужные ClientID, сохрани ранее необходимые записи других клиентов и, если используешь DoT, добавь `127.0.0.1`. Сохрани настройки. Без подходящего идентификатора запросы DoH будут отклоняться, если их источник не разрешён другим правилом.

Официальные инструкции AdGuard: [постоянные клиенты и ClientID](https://adguard-dns.io/kb/ru/adguard-home/clients/) и [безопасный запуск](https://adguard-dns.io/kb/ru/adguard-home/running-securely/).

### Шаг 3. Подключи устройство и проверь DoH

DoH передаёт DNS-запросы по HTTPS. В настройках устройства или приложения выбери пользовательский DoH-сервер и вставь адрес, полученный в шаге 1:

~~~text
https://panel.example.com/dns-XXXXXXXXXXXX
~~~

Если настроил ClientID в шаге 2, добавь его к своему адресу:

~~~text
https://panel.example.com/dns-XXXXXXXXXXXX/ClientID
~~~

Это примеры. Используй свой полный URL из меню сервера, включая его путь.

#### Пример: настройка личного DNS в Happ {#happ-doh}

На телефоне с Happ и обычной подпиской RAW (ссылки подключений, не JSON):

1. Открой настройки маршрутизации своей подписки и её активный профиль. Если профиля нет, создай его на основе стандартного.
2. В настройках удалённого DNS (**Remote DNS**) выбери тип **DoH**, в поле **Remote DNS Domain** вставь полный URL личного DNS, а в **Remote DNS IP** укажи публичный IP своего VPS, на который указывает домен DoH. Сохрани прежние правила маршрутизации.
3. Если хочешь использовать свой DNS и для ресурсов, которые открываются напрямую по правилам профиля, аналогично настрой **Domestic DNS**: DoH, тот же URL и IP. Это необязательно.
4. Сохрани профиль, активируй маршрутизацию для подписки, отключи и снова включи соединение. Изменения применяются при переподключении.

Названия могут отличаться в зависимости от версии приложения. Для JSON-подписки Happ использует отдельные поля **Tunnel DNS**, а настройки маршрутизации и DNS самого Xray определяются полученным JSON. Настройка Tunnel DNS сама по себе не заменяет DNS внутри JSON. Поэтому для этого примера проще использовать RAW-подписку. [Документация Happ по маршрутизации и DNS](https://www.happ.su/main/ru/dev-docs/routing).

#### Проверь результат

Открой на устройстве несколько сайтов, затем в панели AdGuard Home посмотри **Журнал запросов**. Должны появиться новые запросы. Если настроил ClientID, проверь, что они отмечены нужным клиентом. Если записей нет, проверь адрес, правила доступа, активный профиль DNS и переподключение; отдельные приложения могут использовать собственный DNS.

**Готово:** запросы, отправленные на твой личный DNS, видны в журнале. При желании [настрой фильтрацию](#dns-filter).

## Часть 2. Частный DNS на Android через DoT {#device-dot}

Android поддерживает системный пункт «Частный DNS». Он принимает имя хоста, а не HTTPS-ссылку.

!!! warning "DoT доступен из интернета"
    В нашей схеме TCP/853 открыт для интернета; любой, кто знает адрес сервера, сможет отправлять DNS-запросы. Запросы приходят в AdGuard Home от 127.0.0.1 через nginx, поэтому ClientID и индивидуальные правила для устройств не работают. Если нужна индивидуальная защита, выбирай DoH.

### Шаг 1. Подготовь DoT на VPS

При первой установке по [руководству](../start.md) ответь Y на «Установить и настроить AdGuard Home?» и Y на «Включить DNS-over-TLS (DoT) для ваших устройств?». Если хостер отдельно фильтрует порты, разреши TCP/853 в его панели.

Если проект уже установлен с DoT, повторная установка не нужна: используй домен панели. Если DoT не был включён, остановись: отдельного штатного пункта его добавления нет. Не переустанавливай работающий проект ради DoT; можешь выбрать [DoH](#device-doh), если AdGuard Home уже включён.

Сохрани адрес панели AdGuard Home и данные входа, открой её. В установленном проекте адрес можно посмотреть в меню **«6. Данные моего сервера»**.

### Шаг 2. Проверь разрешённых клиентов

В AdGuard Home открой **Настройки → Настройки DNS → Настройки доступа → Разрешённые клиенты**. Если список уже используется, в нём должен быть `127.0.0.1`, иначе запросы DoT будут отклонены. Если списка нет, отдельная настройка для DoT не требуется. Добавление локального адреса разрешает запросы всех устройств, которые подключатся к публичному DoT.

### Шаг 3. Настрой Android

1. Открой настройки сети и найди **«Частный DNS»** (название зависит от оболочки Android).
2. Выбери вариант с именем хоста провайдера.
3. Введи домен панели, например `panel.example.com`, без `https://`, пути и порта.
4. Сохрани настройку и открой сайт. В **Журнале запросов** AdGuard Home должны появиться запросы от `127.0.0.1`. Если нет, проверь домен, доступность TCP/853 и список разрешённых клиентов.

**Готово:** Android использует личный DNS по зашифрованному каналу. При желании [настрой фильтрацию](#dns-filter).

## Совместное использование DoH и DoT {#dns-both}

Для использования обоих способов при новой установке включи AdGuard Home и DoT. Если проект уже установлен с ними, ничего переустанавливать не нужно.

1. Выполни [настройку DoH](#device-doh). Если включил список разрешённых клиентов, сохрани нужные ClientID и добавь `127.0.0.1` для DoT. Если список пуст, отдельная настройка не требуется.
2. Выполни [настройку DoT на Android](#device-dot).
3. Проверь запросы от обоих типов устройств в журнале AdGuard Home.

Без локального адреса DoT перестанет отвечать, если действует список разрешённых клиентов; с ним DoT остаётся доступным любому, кто знает адрес сервера.

## Общая настройка фильтрации и журналов {#dns-filter}

1. Открой выданный адрес панели AdGuard Home и войди с сохранёнными учётными данными.
2. В разделе DNS-фильтров выбери подходящие списки блокировки. Списки можно менять и отключать.
3. В журнале запросов проверь, какие домены обращаются к DNS. Если полезный сервис перестал открываться, проверь его запросы и при необходимости разреши конкретный домен.
4. При необходимости настрой разные правила для постоянных клиентов, созданных при настройке DoH.

DNS-фильтрация блокирует запросы к известным рекламным и отслеживающим доменам. Она также позволяет управлять собственными DNS-правилами. Реклама, загружаемая с домена основного сайта, может оставаться: это свойство самого метода фильтрации.

## Как отключить внешний доступ к DoT

Если DoT больше не нужен, сначала переведи Android на другой DNS, затем подключись к VPS по SSH и получи root. Проверь действующие правила:

```bash
ufw status numbered
```

Если UFW активен и есть штатное разрешение 853/tcp, удали его **на VPS от root**:

```bash
ufw delete allow 853/tcp
```

Повторно проверь правила и доступность порта извне; если UFW неактивен или настроен иначе, ограничь TCP/853 через firewall хостера или действующие правила. DoH продолжит работать через TCP/443. Не меняй SSH и другие разрешения.

## Как сохраняются настройки

При [обновлении проекта на месте](update.md#why-no-update) уже настроенный AdGuard Home сохраняется. AdGuard Home, его конфигурация, фильтры и данные включаются в **полный Backup v3**. При полном Restore на совместимый VPS они восстанавливаются вместе с управляемым стеком. При смене домена панели проект учитывает сертификат дополнительного DoT.
