# Импорт VLESS REALITY: подключаем один сервер 3x-ui к другому

**Создано:** 23 ноября 2026 года.  
**Актуально для:** 3X-UI AUTO NGINX **v2.8.0**, панели **3x-ui v3.11.0** и Xray **26.10.21**. В других версиях расположение кнопок может отличаться.

## Что ты настроишь

Допустим, у тебя есть два сервера. К первому подключаются телефон, компьютер и другие устройства. Второй находится в другой стране и должен стать дополнительным выходом в интернет.

```text
Твоё устройство → Сервер А (входной) → Сервер Б (выходной) → Интернет
```

После инструкции в панели сервера А появится **исходящее подключение (outbound)** к серверу Б. Оно будет доступно для проверок и правил маршрутизации. При этом **пользовательский трафик после импорта сам по себе через сервер Б не пойдёт**: сначала нужно создать правило, которое выберет новый выход. Это следующий шаг в [руководстве по маршрутизации](routing.md).

Инструкция подходит для обычного VLESS REALITY, не только для каскада из нашего установщика. Для готового каскада можно так же добавить третий сервер, а затем настроить [резервирование](balancer.md).

## Перед началом

- На обоих серверах установлен и работает 3x-ui. У тебя есть доступ к обеим веб-панелям.
- Сервер Б принимает VLESS REALITY и доступен из сети сервера А.
- Ты знаешь, какой именно клиент REALITY будет использоваться между серверами.

**Рекомендация:** создай на сервере Б отдельного клиента для межсерверного соединения, например `backup-from-a`. Тогда его можно будет отключить, не затронув обычные подключения своих устройств.

!!! warning "Ссылка VLESS содержит секреты"
    Ссылка вида `vless://…` включает идентификатор клиента (UUID), адрес сервера и параметры REALITY. Не публикуй её в GitHub, обращениях в поддержку, общедоступных скриншотах и логах. Здесь используются только вымышленные имена серверов и тегов.

## 1. Скопируй VLESS REALITY с выходного сервера Б

1. Открой **веб-панель сервера Б**, через который хочешь выходить в интернет. Это не панель сервера А.
2. Перейди в раздел **Клиенты**. Найди клиента, привязанного к нужному входящему подключению **VLESS REALITY**.
3. Если отдельного клиента для межсерверной связи пока нет, создай его, включи и привяжи к нужному REALITY. Для подключения с Vision проверь параметр `xtls-rprx-vision`.
4. В строке клиента нажми значок **ⓘ «Информация о клиенте»**.
5. Найди **ссылку VLESS** и скопируй её целиком. Она начинается с `vless://`. Не путай её со ссылкой на подписку, которая начинается с `https://`.

У ссылки должны быть параметры, соответствующие действующему подключению: адрес, внешний порт, UUID, SNI, публичный ключ REALITY и short ID. Их не нужно переносить по одному: панель импортирует данные из ссылки.

**Если сервер Б установлен нашим проектом:** для управляемого REALITY используется внутренний порт `8443`, но извне подключение принимается через **TCP 443** и nginx stream. В скопированной ссылке должен быть внешний адрес и порт, а не `127.0.0.1:8443`.

## 2. Импортируй подключение на сервере А

Теперь переключись на **веб-панель сервера А**, куда подключены твои устройства.

1. Открой **Xray → Исходящие**.
2. Нажми синюю кнопку **«+ Исходящие»**.
3. В окне создания выбери вкладку **JSON**.
4. Над редактором JSON есть отдельное поле с подсказками `vmess:// vless:// …` и кнопкой **Import**. Вставь в него скопированную `vless://` ссылку.
5. Нажми **Import**. Панель разберёт ссылку и подставит настройки в форму исходящего подключения. В версии 3x-ui v3.11.0 после успешного импорта открывается вкладка **«Основное»**.
6. Задай понятный **тег (Tag)**, например `backup-se`. Тег должен быть уникальным: именно по нему правила маршрутизации будут обращаться к этому серверу.
7. Проверь, что указаны протокол **VLESS**, адрес сервера Б, его внешний порт, UUID, поток `xtls-rprx-vision` (если он используется в исходном клиенте), передача `TCP` и защита `REALITY`. Параметры SNI, public key, fingerprint и short ID должны соответствовать исходной ссылке.
8. Нажми **«Создать»**.

В таблице «Исходящие» появится строка с новым тегом. Если ты видишь пустой адрес, порт `443` с пустым UUID или `security: none`, значит импорт ещё не выполнен: **не создавай исходящее с этими значениями**, вернись к шагу 4.

!!! warning "Создать и сохранить - разные действия"
    Добавление строки меняет подготовленную конфигурацию в интерфейсе. Чтобы применить её к Xray, нажми **«Сохранить»** на основной странице настроек Xray. При применении конфигурации активные соединения могут кратковременно прерваться.

## 3. Проверь подключение через HTTP

Вернись к таблице **Xray → Исходящие** после сохранения.

1. В правой части таблицы над списком выбери режим проверки **HTTP**. Не `TCP`: TCP проверяет доступность соединения, но не подтверждает, что прокси реально передаёт HTTP-запрос.
2. Найди строку `backup-se` и нажми кнопку с **молнией** в столбце «Проверить». Можно воспользоваться «Тестировать все», но тогда панель проверит и остальные исходящие.
3. Дождись результата. Успешный HTTP-тест обычно покажет измеренную задержку в миллисекундах. Ошибка означает, что нужно проверить параметры и связь между серверами.

Успешный тест подтверждает, что Xray сумел выполнить HTTP-проверку через выбранное исходящее подключение. **Он не означает, что трафик твоего телефона уже использует сервер Б.** Для проверки реального маршрута сначала потребуется правило маршрутизации, а затем проверка выходного IP через устройство.

Если тест не проходит, последовательно проверь: работает ли REALITY на сервере Б; верны ли внешний домен и порт; активен ли клиент; не менялись ли UUID, flow и параметры REALITY; доступно ли TCP-соединение между VPS. Сначала исправь причину ошибки, а не меняй настройки всех исходящих сразу.

## 4. Как направить трафик через новый сервер

Открой [«Маршрутизация: как управлять трафиком»](routing.md). Там разобраны правила для отдельных сайтов, клиентов, входящих подключений XHTTP и всего пользовательского трафика.

Например, для проверки можно создать правило только для YouTube, направить его в `backup-se`, сохранить конфигурацию и открыть YouTube с устройства, подключённого к серверу А. Это позволит проверить новый маршрут, не меняя поведение остальных сайтов.

Если у тебя уже настроен [каскад](cascade.md), **не удаляй** созданный установщиком `cascade-exit`: новое подключение `backup-se` можно использовать дополнительно, в том числе как резерв.

## Как вернуть всё обратно

Если ты ещё **не создавал правил**, использующих `backup-se`, достаточно удалить новый исходящий в **Xray → Исходящие** и снова нажать **«Сохранить»**.

Если уже добавил маршрутизацию или балансировщик, сначала убери из них ссылки на `backup-se` и сохрани изменения. Только после этого удаляй исходящее. Клиента на сервере Б можно отключить отдельно, когда убедишься, что он больше не нужен другим серверам.
