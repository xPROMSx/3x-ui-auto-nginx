# Исходящие подключения: добавление другого сервера в 3x-ui

**Создано:** 23 ноября 2026 года.

**Обновлено:** 26 ноября 2026 года. Интерфейс и импорт VLESS сверены с 3x-ui v3.11.0. В других версиях расположение кнопок и поддержка параметров могут отличаться.

## Что ты настроишь

Допустим, у тебя есть два сервера. К первому подключаются телефон, компьютер и другие устройства. Второй находится в другой стране и должен стать дополнительным выходом в интернет.

``` { .text .no-copy }
Твоё устройство → Сервер А (входной) → Сервер Б (выходной) → Интернет
```

После инструкции в панели сервера А появится **исходящее подключение (outbound)** к серверу Б. Оно будет доступно для проверок и правил маршрутизации. При этом **пользовательский трафик после импорта сам по себе через сервер Б не пойдёт**: сначала нужно создать правило, которое выберет новый выход. Это следующий шаг в [руководстве по маршрутизации](routing.md).

Инструкция показывает два распространённых варианта подключения: **VLESS REALITY (TCP)** и **VLESS XHTTP**. В обоих случаях порядок одинаковый: получи ссылку на сервере Б, импортируй её как исходящее на сервере А, сохрани и проверь. Отличаются параметры транспорта. Для готового каскада можно таким же способом добавить третий сервер и затем настроить [резервирование](balancer.md).

**Не путай входящее и исходящее:** входящее (inbound) принимает подключения клиентов, исходящее (outbound) определяет, куда VPS отправляет их трафик. Здесь мы добавляем именно исходящее на уже работающем сервере А, а не создаём ещё одно входящее.

## Перед началом

- На обоих серверах установлен и работает 3x-ui. У тебя есть доступ к обеим веб-панелям.
- Сервер Б принимает VLESS REALITY или VLESS XHTTP и доступен из сети сервера А.
- У тебя есть рабочая ссылка конкретного подключения или возможность создать отдельного клиента на сервере Б. Если XHTTP используется через CDN, CDN должен уже работать.

**Рекомендация:** создай на сервере Б отдельного клиента для межсерверного соединения, например `backup-from-a`. Тогда его можно будет отключить, не затронув обычные подключения своих устройств.

!!! warning "Ссылка VLESS содержит секреты"
    Ссылка вида `vless://…` включает идентификатор клиента (UUID), адрес сервера и параметры подключения. Не публикуй её в GitHub, обращениях в поддержку, общедоступных скриншотах и логах. Здесь используются только вымышленные имена серверов и тегов.

## 1. Скопируй ссылку подключения с выходного сервера Б

1. Открой **веб-панель сервера Б**, через который хочешь выходить в интернет. Это не панель сервера А.
2. Перейди в раздел **Клиенты**. Найди клиента, привязанного к нужному входящему подключению **VLESS REALITY** или **VLESS XHTTP**, которое хочешь использовать.
3. Если отдельного клиента для межсерверной связи пока нет, создай его, включи и привяжи к выбранному входящему. Для REALITY TCP с Vision проверь параметр `xtls-rprx-vision`; не добавляй его в XHTTP вручную.
4. В строке клиента нажми значок **ⓘ «Информация о клиенте»**.
5. Найди **ссылку VLESS** и скопируй её целиком. Она начинается с `vless://`. Не путай её со ссылкой на подписку, которая начинается с `https://`.

Скопируй именно ссылку нужного профиля: у клиента, который привязан к нескольким входящим, их может быть несколько. Для REALITY TCP в ссылке обычно указаны `type=tcp` (или RAW в соответствующих версиях) и `security=reality`, для XHTTP — `type=xhttp` и соответствующий тип защиты. Панель разберёт параметры из ссылки.

**Если сервер Б установлен нашим проектом:** используй внешний адрес и порт из рабочего профиля. Для управляемого REALITY внешний порт обычно TCP/443, а внутренний 8443 не предназначен для подключения другого VPS напрямую. Для XHTTP через nginx или CDN также используй публичный адрес и путь, а не внутренний адрес Xray.

## 2. Импортируй подключение на сервере А

Теперь переключись на **веб-панель сервера А**, куда подключены твои устройства.

1. Открой **Xray → Исходящие**.
2. Нажми синюю кнопку **«+ Исходящие»**.
3. В окне создания выбери вкладку **JSON**.
4. Над редактором JSON есть отдельное поле с подсказками `vmess:// vless:// …` и кнопкой **Import**. Вставь в него скопированную `vless://` ссылку.
5. Нажми **Import**. Панель разберёт ссылку и подставит настройки в форму исходящего подключения. В версии 3x-ui v3.11.0 после успешного импорта открывается вкладка **«Основное»**.
6. Задай понятный **тег (Tag)**, например `backup-se`. Тег должен быть уникальным: именно по нему правила маршрутизации будут обращаться к этому серверу.
7. Проверь импортированные параметры согласно таблице ниже. Не изменяй значения наугад.
8. Нажми **«Создать»**.

| Что проверить | VLESS REALITY (TCP) | VLESS XHTTP |
| --- | --- | --- |
| Протокол, адрес, порт, UUID | VLESS и данные исходной ссылки | VLESS и данные исходной ссылки |
| Транспорт | TCP (RAW) | XHTTP |
| Защита | REALITY | Как в исходной ссылке, например TLS |
| Flow | `xtls-rprx-vision`, если указан в исходном профиле | Как в исходной ссылке; не добавляй Vision вручную |
| Дополнительные поля | SNI, public key, fingerprint, short ID | Host, путь (Path), режим (Mode), параметры TLS или REALITY; дополнительные параметры XHTTP, если используются |

**Host (имя HTTP-хоста) и SNI (имя сервера при установлении TLS-соединения) не всегда совпадают с адресом подключения**, особенно при использовании CDN (сети доставки контента). Если в ссылке есть расширенные параметры XHTTP, панель импортирует поддерживаемые поля, включая данные из `extra`. Сверь их с исходным рабочим профилем, если используются нестандартные настройки. Не меняй путь на `/` и не отключай проверку TLS, чтобы скрыть ошибку подключения.

В таблице «Исходящие» появится строка с новым тегом. Если ты видишь пустой адрес, порт `443` с пустым UUID или неожиданное `security: none` у TLS/REALITY-профиля, значит импорт не соответствует исходной ссылке: **не создавай исходящее с этими значениями**, вернись к шагу 4.

!!! warning "Создать и сохранить - разные действия"
    Добавление строки меняет подготовленную конфигурацию в интерфейсе. Чтобы применить её к Xray, нажми **«Сохранить»** на основной странице настроек Xray. При применении конфигурации активные соединения могут кратковременно прерваться.

## 3. Проверь подключение через HTTP {#http-test}

Вернись к таблице **Xray → Исходящие** после сохранения.

1. В правой части таблицы над списком выбери режим проверки **HTTP**. Не `TCP`: TCP проверяет доступность соединения, но не подтверждает, что прокси реально передаёт HTTP-запрос.
2. Найди строку `backup-se` и нажми кнопку с **молнией** в столбце «Проверить». Можно воспользоваться «Тестировать все», но тогда панель проверит и остальные исходящие.
3. Дождись результата. Успешный HTTP-тест обычно покажет измеренную задержку в миллисекундах. Ошибка означает, что нужно проверить параметры и связь между серверами.

Успешный тест подтверждает, что Xray сумел выполнить HTTP-проверку через выбранное исходящее подключение. **Он не означает, что трафик твоего телефона уже использует сервер Б.** Для проверки реального маршрута сначала потребуется правило маршрутизации, а затем проверка выходного IP через устройство.

Если тест не проходит, последовательно проверь: работает ли выбранное подключение на сервере Б; верны ли внешний домен и порт; активен ли клиент; совпадают ли UUID, транспорт, flow и параметры защиты. Для XHTTP дополнительно проверь Host, путь, режим, параметры TLS/REALITY и работу CDN (если он используется). Проверь доступность TCP между VPS. Сначала исправь причину ошибки, а не меняй настройки всех исходящих сразу.

## 4. Как направить трафик через новый сервер

Открой [«Маршрутизация: как управлять трафиком»](routing.md). Там разобраны правила для отдельных сайтов, клиентов, входящих подключений XHTTP и всего пользовательского трафика.

Например, для проверки можно создать правило только для YouTube, направить его в `backup-se`, сохранить конфигурацию и открыть YouTube с устройства, подключённого к серверу А. Это позволит проверить новый маршрут, не меняя поведение остальных сайтов.

Если у тебя уже настроен [каскад](cascade.md), **не удаляй** созданный установщиком `cascade-exit`: новое подключение `backup-se` можно использовать дополнительно, в том числе как резерв.

## Как вернуть всё обратно

Если ты ещё **не создавал правил**, использующих `backup-se`, достаточно удалить новый исходящий в **Xray → Исходящие** и снова нажать **«Сохранить»**.

Если уже добавил маршрутизацию или балансировщик, сначала убери из них ссылки на `backup-se` и сохрани изменения. Только после этого удаляй исходящее. Клиента на сервере Б можно отключить отдельно, когда убедишься, что он больше не нужен другим серверам.
