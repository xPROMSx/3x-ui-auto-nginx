# Telegram WEB-прокси: HTTPS, Telemt и собственный сайт

Telegram Web Proxy Manager (TWPM) - наш отдельный бесплатный проект для установки и обслуживания Telegram-прокси. Он интегрирован в меню 3X-UI AUTO NGINX: на одном VPS можно использовать обычные подключения Xray и отдельный прокси непосредственно в Telegram.

**Выбери свой сценарий:**

- [Обычный VPS, с которого Telegram доступен напрямую](#direct-install).
- [Российский входной VPS каскада, с которого Telegram недоступен напрямую](#cascade-socks).

В обоих случаях телефон или компьютер подключается к Telegram через готовую ссылку WEB-прокси. Отдельное VPN-приложение на устройстве для этого не требуется.

## 1. Что такое WEB Proxy и зачем он нужен

WEB - тип прокси, разработанный командой Telegram. В отличие от обычного MTProxy с имитацией TLS (FakeTLS), WEB переносит потоки MTProxy внутри настоящего HTTPS-соединения. В реализации Telegram Desktop приложение может использовать встроенный веб-компонент (WebView) для передачи данных через веб-транспорт, сохраняя обычное шифрование MTProto.

Мы используем совместимую реализацию WEB в **Telemt**. В установке TWPM выбран HTTPS-транспорт. Настоящий nginx принимает TLS-соединение с действительным сертификатом Let's Encrypt, а Telemt обрабатывает прокси-запросы. Запросы обычного посетителя направляются на сайт-прикрытие.

<div class="landing-route no-copy" aria-label="Маршрут Telegram WEB">Telegram → HTTPS :443 → nginx → Telemt → Telegram</div>

<div class="landing-route no-copy" aria-label="Маршрут обычного посетителя">Браузер → HTTPS :443 → nginx → сайт-прикрытие</div>

### Что даёт сочетание с 3X-UI AUTO NGINX

- **Настоящий HTTPS.** Соединение использует обычный TLS с сертификатом для твоего домена, а не имитацию рукопожатия.
- **Рабочий сайт на домене.** При открытии адреса в браузере видны страницы, меню и иллюстрации. Для новой установки менеджер выбирает одну из трёх тематик: растения, ночное небо или домашняя кухня. Оформление персонализируется, страницы адаптированы для телефона и не требуют внешних ресурсов.
- **Общий nginx.** На TCP/443 уже работают панель и подключения 3X-UI. Nginx выбирает нужный сервис по имени домена в TLS (SNI). Для TWPM нужен отдельный домен, но не отдельный публичный порт или дополнительный веб-сервер.
- **Собственный маршрут до Telegram.** Telemt может выходить напрямую или через SOCKS5. На входном VPS мы можем использовать готовое исходящее подключение каскада.
- **Независимое управление.** TWPM устанавливает и обслуживает Telemt, свой сайт и сертификат. Обновление Telemt проверяет новую версию и предусматривает возврат к предыдущей рабочей при неудаче.

С точки зрения внешнего наблюдателя начальное подключение идёт к твоему домену по HTTPS на TCP/443. Обычный запрос к сайту получает его реальные страницы. Это полезное отличие от прокси, который только имитирует TLS или показывает пустую заглушку.

[Спецификация WEB от Telegram](https://github.com/telegramdesktop/tproxy-server/blob/master/PROTOCOL.md) · [Описание WEB в Telemt](https://github.com/telemt/telemt/blob/main/docs/WEB/WEB_PROXY.ru.md)

## 2. Что потребуется

- VPS с Ubuntu 24.04 или 26.04, архитектура x86_64 или ARM64, рабочий 3X-UI AUTO NGINX. [Первый запуск проекта](../start.md).
- SSH-доступ с правами root.
- Свободный домен или поддомен для TWPM. Например, `tg.example.com`. Это пример, замени его своим.
- DNS-запись A этого домена должна указывать на публичный IPv4 VPS, на котором устанавливаешь TWPM. Если есть AAAA, проверь её соответствие этому серверу. Для схемы с прямым подключением к VPS в Cloudflare выбери **DNS only** (серое облако).
- Доступные извне TCP/80 (выпуск сертификата) и TCP/443 (сайт и прокси). TWPM не меняет firewall самостоятельно.
- Версия приложения Telegram, поддерживающая тип прокси WEB.

Домен TWPM должен отличаться от доменов панели, REALITY, Vision и других действующих сайтов nginx. На российском каскаде запись A указывает именно на **российский входной VPS**, а не на зарубежный выход.

## 3. Выбираем маршрут до Telegram

SOCKS5 - промежуточное подключение, через которое Telemt может отправлять запросы к серверам Telegram. Оно находится на стороне VPS, а не на телефоне.

| Сценарий | Выбор при установке |
|---|---|
| VPS напрямую соединяется с Telegram | `N`, SOCKS5 не нужен |
| Прямой доступ с VPS заблокирован, настроен каскад | `Y`, локальный SOCKS5 через Xray |
| Уже есть другой доступный SOCKS5 без авторизации | `Y`, его адрес и порт |

### Обычный VPS {#direct-install}

На VPS от root проверь доступ к API Telegram:

```bash
curl --noproxy '*' -fsS --connect-timeout 10 --max-time 30 https://api.telegram.org/ -o /dev/null && echo OK
```

Если появилось `OK`, HTTPS-запрос прошёл. Это предварительная проверка связи, а работу самого Telegram проверим после установки. Если прямое подключение работает, переходи к [установке TWPM](#install-twpm), выбрав SOCKS5 = N.

### Российский входной VPS: SOCKS5 через каскад {#cascade-socks}

Если Telegram недоступен непосредственно с российского VPS, сначала подготовь [каскад из двух VPS](cascade.md). На входном VPS в Xray должно быть рабочее исходящее подключение `cascade-exit` к зарубежному серверу.

<div class="landing-route no-copy" aria-label="Маршрут Telegram через каскад">Telegram → HTTPS → nginx → Telemt → локальный Mixed (SOCKS5) → Xray → зарубежный VPS → Telegram</div>

Так телефон соединяется с российским сервером, а Telemt обращается к Telegram через зарубежный. Обычные клиентские подключения 3X-UI продолжат использовать свои правила. На выходном сервере TWPM для этой схемы устанавливать не нужно.

#### Шаг 1. Создай локальное входящее Mixed

Всё делаем в панели **российского входного VPS**. Перед правкой сохрани [Backup](backup.md). Применение изменений Xray может ненадолго прервать активные подключения.

!!! warning "SOCKS5 без авторизации должен быть только локальным"
    Обязательно укажи адрес `127.0.0.1`. Не оставляй адрес пустым, не используй `0.0.0.0`, `::` или публичный IP. Не открывай выбранный порт в UFW или firewall хостера. Иначе посторонние могут использовать прокси без пароля.

1. Открой **«Входящие» → «Создать подключение»**.
2. На вкладке **«Основное»** заполни параметры:

    | Поле | Значение |
    |---|---|
    | Включить | Да |
    | Примечание | `TWPM-SOCKS` |
    | Протокол | `mixed` |
    | Адрес | `127.0.0.1` |
    | Порт | `10808` (пример свободного порта) |
    | Auth | `noauth` |
    | UDP | Выключено |
    | Исключить из подписок | Включено, если поле доступно |

    Mixed умеет принимать SOCKS5 и HTTP-прокси на одном порту. Telemt будет использовать только SOCKS5. Если порт 10808 уже занят, выбери другой свободный порт и используй его далее везде.

3. Открой вкладку **«Сниффинг»**, включи его. Если показаны переключатели распознавания HTTP и TLS, оставь их включёнными. **«Только маршрутизация»** включи, **«Только метаданные»** оставь выключенным. Сниффинг помогает Xray определить назначение трафика по доступным заголовкам; режим «Только маршрутизация» не подменяет исходное назначение соединения. Наше отдельное правило будет работать по тегу входящего независимо от распознанного домена.
4. Нажми **«Создать»**. Убедись, что подключение появилось в списке и включено.

Проверь на российском VPS от root:

```bash
ss -ltnp 'sport = :10808'
```

В локальном адресе должен быть `127.0.0.1:10808`, а не `0.0.0.0:10808` или `[::]:10808`. Если адрес другой, исправь его в панели прежде, чем продолжать.

#### Шаг 2. Направь весь трафик Mixed в cascade-exit

На российском VPS в панели открой **«Конфигурации Xray» → «Маршрутизация» → «Маршрутизация»**. Добавь отдельное правило кнопкой над таблицей.

| Поле | Значение |
|---|---|
| Включить | Да |
| Комментарий | `TWPM - EXIT` |
| Теги входящих | Выбери фактический тег созданного Mixed (по примечанию TWPM-SOCKS) |
| Тег исходящего | `cascade-exit` |
| Тег балансировщика | Пусто |
| Домен, IP, Порт, Пользователь и остальные условия | Пусто |

Тег входящего - внутренний идентификатор подключения Xray, не обязательно совпадающий с его примечанием. Выбирай существующее подключение из списка.

Нажми **«Создать»**. Перемести новое правило выше общих `CASCADE - RU`, `CASCADE - RU2` и `CASCADE - EXIT`, а также других общих правил, способных перехватить трафик этого Mixed. Служебные правила API и защиты внутренних адресов сохраняй. Нажми общее **«Сохранить»** в конфигурации Xray.

Xray применяет первое подходящее правило. Мы не указываем геоданные Telegram или конкретные IP: правило применяется только к созданному входящему и направляет весь его обычный внешний трафик на зарубежный сервер. Поэтому нет необходимости менять российские исключения для других пользователей.

Если у тебя уже настроен [балансировщик каскада](balancer.md), можно вместо исходящего выбрать существующий тег балансировщика. Заполняй только одно из этих полей.

#### Шаг 3. Проверь SOCKS5 до установки TWPM

На российском VPS от root выполни:

```bash
curl --noproxy '' --proxy socks5h://127.0.0.1:10808 --connect-timeout 10 --max-time 30 https://api.ipify.org
```

При обычном прямом выходе на зарубежном VPS команда должна показать его публичный IP. Если на выходе используется другой прокси, результат будет соответствовать его адресу.

Теперь проверь Telegram через тот же маршрут:

```bash
curl --noproxy '' --proxy socks5h://127.0.0.1:10808 -fsS --connect-timeout 10 --max-time 30 https://api.telegram.org/ -o /dev/null && echo OK
```

`socks5h` означает, что curl передаёт имя назначения SOCKS5-прокси. При успешном запросе появится `OK`. Если проверка не прошла, проверь статус Xray, доступность `cascade-exit`, тег входящего и порядок правил. Продолжай установку после успешной проверки.

## 4. Установи TWPM через меню {#install-twpm}

Подключись по SSH к VPS, где будет Telegram-прокси. На российском каскаде это входной VPS. Если вошёл под обычной учётной записью, выполни на сервере:

```bash
sudo -i
```

Из каталога с ранее скачанным установщиком **на VPS от root** запусти:

```bash
bash x-ui-latest.sh
```

Если файл не сохранился, скачай актуальный установщик из [официального релиза](../start.md). Не выбирай пункт «Установка» 3X-UI: существующий стек нам менять не нужно.

Выбери **2. Русский**, затем **4. Telegram Web Proxy Manager**.

При первом запуске появится вопрос:

``` { .text .no-copy }
Хотите перейти к установке Telegram Web Proxy Manager? [y/N]:
```

Ответь `y`. Откроется отдельный менеджер. При выборе языка выбери русский, затем **1. Установить Telegram-прокси**.

Ответь на вопросы:

| Вопрос TWPM | Что ввести |
|---|---|
| Домен WEB-прокси | Твой свободный поддомен |
| Публичный IPv4 | Enter, если предложенный IP совпадает с публичным IPv4 этого VPS и DNS A |
| Подключаться через SOCKS5? [y/N] | `N` для прямого выхода; `Y` для подготовленного каскада |
| Хост SOCKS [127.0.0.1] | При Y для каскада нажми Enter |
| Порт SOCKS | При Y для каскада введи `10808` или выбранный ранее порт |

Хост и порт SOCKS спрашиваются только при выборе Y. Менеджер проверяет доступ через SOCKS5 запросом к Telegram API, получает сертификат, настраивает маршрутизацию nginx, устанавливает Telemt, создаёт сайт и показывает готовую ссылку подключения.

## 5. Подключись к Telegram и проверь результат

1. Открой выданную ссылку `tg://webproxy?…` на устройстве с поддержкой WEB. Подтверди добавление прокси и включи его в Telegram.
2. Проверь, что мессенджер подключился: отправь сообщение, открой канал и загрузи медиа.
3. Открой свой домен TWPM в обычном браузере через HTTPS. Должен открыться сайт с действительным сертификатом. Перейди по нескольким страницам.
4. Проверь остальные подключения 3X-UI, если оба проекта работают на одном VPS.

!!! warning "Не публикуй ссылку"
    Ссылка WEB содержит секрет доступа. Храни её в безопасном месте и не публикуй скриншоты с ней. Это отдельная ссылка Telegram, не подписка 3X-UI.

## 6. Обслуживание

В дальнейшем открывай пункт **4. Telegram Web Proxy Manager** основного меню либо запускай на VPS от root:

```bash
telegram-web-proxy-manager
```

В русском меню:

| Пункт | Назначение |
|---|---|
| 1. Установить Telegram-прокси | Новая установка или проверка существующей |
| 2. Обновить Telemt | Проверка и безопасное обновление движка |
| 3. Проверить состояние | Проверка действующей установки |
| 4. Проверить и перезапустить службы | Проверка конфигурации, перезапуск Telemt и перечитывание nginx |
| 5. Показать ссылку подключения | Повторный вывод секретной ссылки |
| 6. Удалить Telegram-прокси | Удаление с подтверждением |
| 0. Выход | Закрыть менеджер |

Если Telegram перестал подключаться, сначала проверь состояние через пункт 3. В схеме с каскадом повтори проверку SOCKS5, затем проверь сайт через браузер. Не переустанавливай весь 3X-UI для исправления Telegram-прокси.

### Backup и перенос VPS

TWPM обслуживается отдельно. Backup v3 проекта 3X-UI не заменяет резервное копирование данных самого Telemt. Полный Restore 3X-UI на сервере с TWPM блокируется, чтобы не затереть его конфигурацию nginx. Перед Restore сохрани необходимые данные TWPM отдельно и следуй сообщению менеджера об удалении TWPM; после Restore установи его заново. При новой установке ссылка Telegram изменится.

Если SOCKS5 больше не нужен, сначала удали TWPM штатным меню (если отказываешься от прокси), затем удали только своё правило `TWPM - EXIT` и входящее `TWPM-SOCKS` в панели, сохрани конфигурацию Xray. Не удаляй общие правила каскада и чужие подключения.
