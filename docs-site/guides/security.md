# Расширенная безопасность VPS

## Настройки, которые не придётся собирать вручную

После аренды VPS предстоит защитить доступ по SSH, настроить firewall, сертификаты, системный DNS и своевременные обновления. Установщик 3X-UI AUTO NGINX выполняет эти задачи при первом запуске, а для дополнительных мер безопасности предлагает ответить **Y** на вопрос **«Усилить безопасность VPS?»**. Это рекомендуемый выбор, уже выбранный по умолчанию в русском меню.

Защита касается самого VPS, на котором работают панель 3x-ui, Xray и nginx. Она дополняет защищённые подключения пользователей.

## Что настраивает проект

| Функция | Что делает | Чем полезна |
| --- | --- | --- |
| **Fail2ban** | Следит за неудачными SSH-входами и временно блокирует повторяющиеся попытки | Защищает учётные записи от автоматического подбора пароля |
| **Шифрованный DNS сервера** | Подключает глобальные DNS-серверы Cloudflare и Google через DNS-over-TLS (DoT) | Скрывает глобальные DNS-запросы от наблюдения и подмены на пути до DNS-провайдера |
| **Автообновления безопасности** | Настраивает штатные механизмы APT и unattended-upgrades для Ubuntu или Debian | Обновляет уязвимые системные пакеты, включая nginx и ядро |
| **Перезагрузка после обновлений** | Запускает перезагрузку в заданное ночное время, если она необходима | Применяет изменения, которым нужен новый запуск ОС |
| **Сетевой экран (firewall, UFW)** | Разрешает нужные входящие подключения и закрывает доступ к остальным портам; перед включением сохраняет возможность входа по SSH | Уменьшает число доступных извне служб и защищает VPS от нежелательных сетевых подключений, не оставляя администратора без доступа |
| **HTTPS и сертификаты** | Выпускает сертификаты Let's Encrypt и организует их автоматическое продление | Защищает соединения с панелью, подписками и веб-сервисами |

**Сетевой экран ограничивает доступ к серверу извне.** Сканирование открытых портов не даст доступа к службам, для которых входящие подключения закрыты. При этом установщик учитывает действующий порт SSH и настраивает его разрешение до включения UFW, чтобы ты мог продолжать управлять VPS.

Независимо от выбора расширенной безопасности установщик также может подготовить swap-файл на 1 ГиБ, если swap отсутствует и система подходит для этого. Swap помогает при нехватке оперативной памяти.

### Пример из реальной практики: исправления nginx в ноябре 2026 года

19 и 20 ноября 2026 года Ubuntu выпустила обновления безопасности nginx для поддерживаемых выпусков, включая Ubuntu 24.04 и 26.04. Уязвимости касались обработки HTTPS/TLS и запросов и могли приводить, в зависимости от проблемы и версии, к отказу в обслуживании или раскрытию данных. Обновления доставлялись через штатный менеджер пакетов: [USN-9159-1](https://ubuntu.com/security/notices/USN-9159-1) и [USN-9182-1](https://ubuntu.com/security/notices/USN-9182-1).

18 ноября Ubuntu также устранила [уязвимость needrestart (USN-9151-1)](https://ubuntu.com/security/notices/USN-9151-1), позволявшую локальному пользователю повысить привилегии. Исправления были выпущены для Ubuntu 24.04 и 26.04.

**Именно ради таких ситуаций мы настраиваем автоматические обновления безопасности.** Не нужно каждый день искать публикации об уязвимостях и вручную обновлять системные пакеты. Установленная политика сама проверяет репозитории и применяет доступные исправления.

### Когда проходят обновления

Время указано **по часовому поясу самого VPS**.

| Время | Действие |
| --- | --- |
| 02:30 | Обновление списков пакетов |
| 02:50 | Установка обновлений безопасности |
| 04:38 | Перезагрузка, если она требуется после обновлений |

!!! warning "Ночная перезагрузка"
    Если система запрашивает перезагрузку, она состоится в 04:38 **в том числе при активных подключениях**. На время перезапуска VPS они прервутся. Это расписание следует учитывать, если сервер обслуживает пользователей круглосуточно.

## Отдельно о DNS и SSH

**DNS самого VPS** и **личный DNS устройств** - две самостоятельные функции. Первый включается в расширенной безопасности и защищает глобальные запросы сервера. Второй работает через дополнительный AdGuard Home и позволяет фильтровать запросы телефонов и компьютеров. Подробнее - в [руководстве по личному DNS](dns.md).

**SSH-ключи** позволяют входить без пароля учётной записи и хорошо дополняют Fail2ban. После проверки входа по ключу можно отключить парольную аутентификацию, чтобы исключить подбор пароля по SSH. Установщик сохраняет действующие способы входа, чтобы не лишить тебя доступа. В [руководстве по SSH-ключам](ssh-keys.md) показаны два способа: через Termius (рекомендуем) и PowerShell в Windows 11. После проверки ключа рекомендуем [отключить вход по паролю через SSH](ssh-password.md).

## Что проверить после установки

Подключись к VPS по SSH. Если вошёл не под root, выполни `sudo -i`. Запусти менеджер от root, открой пункт **«Данные моего сервера»** и изучи итоговую информацию. Если включал расширенную безопасность, дополнительно можно проверить её средствами Ubuntu или Debian.

**На VPS с правами root:**

```bash
systemctl is-active fail2ban
systemctl is-enabled apt-daily.timer apt-daily-upgrade.timer
systemctl list-timers apt-daily.timer apt-daily-upgrade.timer --no-pager
resolvectl status
```

Ожидаемые результаты: `fail2ban` активен, таймеры включены, а в `resolvectl status` для глобальных серверов отображается режим DNS-over-TLS. Запросы DNS отдельных сетевых интерфейсов могут использовать собственные маршруты и настройки.

Отдельно проверь firewall **на VPS от root**:

```bash
ufw status verbose
```

Если UFW включён, ожидается `Status: active`. Сверь разрешённый SSH-порт и порты нужных сервисов; если UFW неактивен, не считай его защитой. Не включай firewall вслепую: сначала проверь правила SSH. При изменении правил оставь текущий сеанс открытым и проверь новый вход.

Для просмотра доступных обновлений без установки:

```bash
apt list --upgradable
```

Эта команда только показывает список. Обновления безопасности установит настроенный таймер.
