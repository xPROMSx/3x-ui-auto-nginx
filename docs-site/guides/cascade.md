# Каскад из двух VPS: пошаговая настройка

**Инструкция для 3X-UI AUTO NGINX v2.8.0**

- Панель: **3x-ui v3.11.0**
- Ядро: **Xray 26.10.21**
- Проверено по коду релиза от **23 ноября 2026 года**

В следующих версиях проекта названия пунктов меню и порядок настройки могут измениться.

**С чего начать:** сначала ознакомься с [требованиями к серверам и доменам](#cascade-requirements), затем выбери свою ситуацию.

- [У меня два новых VPS](#cascade-new-exit) - подготовь зарубежный, затем российский сервер.
- [У меня уже есть зарубежный VPS](#cascade-existing-exit) - проверь его, затем подготовь российский.
- [У меня уже установлены оба VPS](#cascade-existing-both) - проверь готовность без переустановки.

Когда оба сервера готовы, переходи к [соединению серверов](#cascade-connect).

## Что такое каскад и зачем он нужен

Каскад позволяет объединить два VPS в одну цепочку. VPS (Virtual Private Server) - виртуальный сервер, который ты арендуешь у хостинг-провайдера и настраиваешь самостоятельно.

В обычной схеме устройство подключается непосредственно к зарубежному VPS. В каскаде появляется промежуточный сервер, например в России.

``` { .text .no-copy }
Телефон, компьютер или роутер
             |
             v
    Входной VPS (Россия)
             |
             v
    Выходной VPS (Европа)
             |
             v
          Интернет
```

У каждого сервера своя задача.

**Входной VPS** принимает подключения от твоих устройств. Именно его адрес указывают в клиентских приложениях. Он определяет, куда направить трафик: непосредственно в интернет или на второй сервер.

**Выходной VPS** принимает трафик от входного сервера и отправляет его к конечным сайтам и сервисам. При прямом выходе через него сайты видят публичный IP-адрес выходного VPS.

Такая схема может помочь, когда прямое подключение к зарубежному серверу работает нестабильно, но соединения через российский VPS остаются доступными.

Однако каскад не гарантирует обход любых блокировок. Между российским и зарубежным VPS тоже должно работать соединение. Кроме того, дополнительный сервер увеличивает задержку и может ограничивать итоговую скорость.

### Как распределяется трафик

По умолчанию 3X-UI AUTO NGINX настраивает следующие правила:

- Российские домены из `geosite:category-ru` открываются напрямую через входной VPS.
- Российские IP-адреса из `geoip:ru` тоже используют прямой выход.
- Остальной подходящий трафик передаётся через зарубежный VPS, если его не обработали более ранние правила.

Это означает, что каскад **не отправляет абсолютно весь трафик через зарубежный сервер**. При необходимости маршрутизацию российских сайтов можно изменить после настройки.

## 1. Что потребуется {#cascade-requirements}

Для начала подготовь:

1. Два VPS: один для входящих подключений, второй для выхода в интернет.
2. Поддерживаемую ОС на каждом сервере: Ubuntu 24.04 LTS, Ubuntu 26.04 LTS или Debian 13. Чистая ОС нужна только для новой установки.
3. По два домена или поддомена на каждый VPS: один для панели, другой для REALITY.
4. SSH-доступ к обоим серверам с возможностью работать от `root`.
5. Доступ к DNS-записям доменов, чтобы направить их на соответствующие серверы.
6. Работающий 3X-UI AUTO NGINX на обоих VPS к моменту соединения. Если сервер уже установлен, не переустанавливай его.

На каждом сервере должны быть доступны входящие порты TCP 80 и 443, UDP 443. Если используешь DNS-over-TLS (DoT), дополнительно нужен TCP 853.

Для каскада не требуется устанавливать отдельную панель управления, создавать вручную межсерверный VPN или редактировать конфигурацию Xray.

### Пример распределения доменов

Допустим, у тебя есть домен `example.com`.

| Назначение | Поддомен |
|---|---|
| Панель российского VPS | `ru-panel.example.com` |
| REALITY российского VPS | `ru-reality.example.com` |
| Панель зарубежного VPS | `eu-panel.example.com` |
| REALITY зарубежного VPS | `eu-reality.example.com` |

Это вымышленные адреса. Замени их своими.

Оба российских поддомена должны указывать на IP российского VPS. Оба зарубежных - на IP зарубежного.

Для IPv4 обычно создаются DNS-записи типа `A`. Если ты используешь IPv6, проверь также записи `AAAA`: они не должны указывать на другой или недоступный сервер.

|---|---|

| Оперативная память | 1 ГБ |

Но 1 ГБ ОЗУ и 10 ГБ диска - минимальная конфигурация, а не универсальная рекомендация. Для дополнительных сервисов, крупных журналов и резервных копий лучше рассмотреть 2 ГБ ОЗУ и 20 ГБ диска либо возможность расширения ресурсов.

## 3. Подготовь серверы к каскаду

Установка выполняется **только на новых VPS**. Если один или оба уже работают, используй соответствующие разделы проверки готовности. Каскад настраивается после подготовки обоих серверов.

### Новый зарубежный VPS {#cascade-new-exit}

#### Шаг 1. Подключись к зарубежному VPS

Сначала подготовим выходной сервер.

Подключись по SSH через Termius или PowerShell в Windows 11. [Настройка SSH-ключей](ssh-keys.md).

Например, **на своём компьютере**:

```powershell
ssh root@IP_ЗАРУБЕЖНОГО_VPS
```

Вместо `IP_ЗАРУБЕЖНОГО_VPS` укажи адрес сервера.

Если хостер запрещает прямой вход root, подключись под выданной учётной записью, например `ubuntu`. Затем **на VPS** выполни:

```bash
sudo -i
```

Перед установкой проверь пользователя:

```bash
whoami
```

Должно появиться `root`. Все дальнейшие серверные команды и запуск менеджера выполняй от root. При новом SSH-подключении под обычным пользователем снова выполни `sudo -i`.

#### Шаг 2. Установи проект

**Внимание:** установка предназначена для чистого VPS. Если сервер уже использовался для 3X-UI AUTO NGINX, повторная установка может удалить управляемые данные, конфигурацию nginx и базу панели. Сначала сохрани Backup за пределами VPS.

На зарубежном сервере, в терминале с правами root, выполни:

```bash
curl -fSL https://github.com/xPROMSx/3x-ui-auto-nginx/releases/latest/download/x-ui-latest.sh -o x-ui-latest.sh && bash x-ui-latest.sh
```

Команда скачает установщик из последнего опубликованного релиза и запустит его.

При первом запуске выбери язык:

``` { .text .no-copy }
1. English
2. Русский
```

Выбери `2`.

В главном меню:

``` { .text .no-copy }
1. Установка
2. Смена доменов
3. Резервные копии
4. Telegram Web Proxy Manager
5. Каскад
6. Данные моего сервера
0. Выход
```

На чистом VPS выбери **1. Установка**.

#### Шаг 3. Ответь на вопросы установщика

Для обычной конфигурации каскада достаточно стандартных настроек.

| Вопрос | Что выбрать |
|---|---|
| Домен панели | Поддомен панели зарубежного VPS |
| Домен REALITY | Поддомен REALITY зарубежного VPS |
| Расширенная безопасность | `Y`, если подходят предложенные настройки |
| Дополнительные подключения | `N`, если они пока не нужны |
| Российские сайты через WARP | Для первой настройки можно выбрать `N` |
| AdGuard Home | По желанию, для простого каскада `N` |
| Автоматическое создание клиента | По желанию |

Каскаду обязательно требуется стандартное подключение **VLESS + REALITY**. Оно создаётся установщиком автоматически.

Дополнительный VLESS XTLS Vision включать не нужно: для межсерверной связи каскад использует существующий REALITY с параметром Vision.

Cloudflare WARP на выходном VPS разрешён. Однако для первой настройки проще оставить его отключённым, чтобы не усложнять проверку маршрутов.

После установки сохрани адрес панели, логин и пароль.

Открой панель в браузере и убедись, что Xray запущен и стандартное подключение REALITY включено.

Зарубежный VPS готов. Теперь перейди к [подготовке российского VPS](#cascade-new-entry) или [проверке уже установленного российского VPS](#cascade-existing-both).

### Уже установлен зарубежный VPS {#cascade-existing-exit}

Открой его панель 3x-ui, проверь, что Xray запущен, стандартное входящее VLESS REALITY включено и доступно извне через TCP/443. Убедись, что домены панели и REALITY указывают на этот сервер и ты можешь войти по SSH с правами root. WARP на выходном сервере допустим. Повторную установку не запускай.

Если российский VPS новый, переходи к следующему разделу. Если он уже установлен, перейди к [проверке обоих серверов](#cascade-existing-both).

### Новый российский VPS {#cascade-new-entry}

Теперь подключись по SSH к российскому серверу.

У HSVDS для Ubuntu прямой вход root по умолчанию запрещён. Используй учётную запись, указанную в карточке VPS (например, `ubuntu`). То же правило действует для любого хостера, который не разрешает прямой вход root.

После подключения под обычным пользователем **на VPS** получи права root:

```bash
sudo -i
```

Проверь:

```bash
whoami
```

Должно появиться `root`. Если ты уже подключился под root, команда `sudo -i` не нужна. Не требуется разрешать прямой вход root в настройках SSH.

**Внимание:** пункт «1. Установка» заменяет управляемые данные. Если российский VPS уже установлен, не запускай установку и перейди к [проверке обоих серверов](#cascade-existing-both).

Только после этого **на чистом российском VPS от root** выполни команду установки:

```bash
curl -fSL https://github.com/xPROMSx/3x-ui-auto-nginx/releases/latest/download/x-ui-latest.sh -o x-ui-latest.sh && bash x-ui-latest.sh
```

Выбери русский язык и пункт **1. Установка**.

Здесь есть одно существенное отличие.

**На вопрос «Скрыть IP вашего VPS от российских сайтов через Cloudflare WARP?» обязательно ответь `N`.**

В русском меню WARP предлагается включить по умолчанию. Но на входном сервере он несовместим с каскадом.

Если выбрать `Y`, подключить выходной VPS позднее не получится, пока не будут удалены элементы WARP из конфигурации Xray.

Для нового российского VPS используй следующие ответы:

| Вопрос | Что выбрать |
|---|---|
| Домен панели | Поддомен панели российского VPS |
| Домен REALITY | Поддомен REALITY российского VPS |
| Расширенная безопасность | `Y`, если подходят настройки |
| Дополнительные подключения | `N`, если не нужны |
| Российские сайты через WARP | **`N`** |
| AdGuard Home | По желанию, для простого каскада `N` |
| Автоматическое создание клиента | `Y` для проверки с устройства |

После завершения установки проверь:

- открывается ли панель российского VPS;
- работает ли Xray;
- создан ли обычный клиент;
- доступна ли его подписка.

Теперь перейди к проверке готовности обоих серверов.

### Оба VPS уже установлены: проверка готовности {#cascade-existing-both}

Убедись, что на обоих VPS работают панель, Xray и стандартное REALITY. На входном сервере нужен обычный клиент или подписка для проверки трафика. Проверь SSH-доступ к обоим VPS и сохрани актуальные [резервные копии](backup.md) вне серверов перед изменением конфигурации.

**На российском входном VPS WARP не должен быть настроен.** Если он уже есть, сначала выполни [удаление конфликтующих настроек WARP](#cascade-remove-warp). На зарубежном выходном VPS WARP допустим. Если каскад уже подключён, не создавай ключ повторно: перейди к [проверке работающего каскада](#cascade-verify).

Когда оба сервера готовы, переходи к соединению.

## 4. Создаём ключ каскада на зарубежном VPS {#cascade-connect}

**Начинать настройку нужно с выходного сервера.**

Подключись к нему по SSH. Если вошёл не под root, сначала выполни `sudo -i`. **На зарубежном VPS от root** запусти скачанный ранее установщик из каталога, где ты его сохранил:

```bash
bash x-ui-latest.sh
```

Если файл установщика не сохранился, скачай его заново по команде из предыдущего раздела. Не выбирай повторную установку: для работающего сервера нам нужен только менеджер.

В главном меню открой:

**5. Каскад**

Появится меню:

``` { .text .no-copy }
1. Создать ключ (выходной сервер)
2. Подключить выходной сервер (входной сервер)
3. Состояние
4. Отключить
0. Назад
```

Выбери **1. Создать ключ (выходной сервер)**.

Менеджер попросит логин и пароль от веб-панели 3X-UI этого сервера.

Вводимые учётные данные скрыты и не сохраняются менеджером.

После успешной авторизации установщик:

1. Найдёт стандартное REALITY-подключение.
2. Создаст в нём отдельного клиента с именем `cascade`.
3. Привяжет клиента к этому REALITY-подключению.
4. Получит из панели ключ-ссылку для подключения.
5. Покажет ссылку, начинающуюся с `vless://`.

Скопируй ссылку целиком.

**Не публикуй её в чатах, на форумах или в GitHub Issues.** Внутри находятся данные для подключения к выходному серверу. Человек с такой ссылкой сможет использовать созданного клиента.

### Что появилось в панели 3X-UI

Открой веб-панель зарубежного сервера и перейди в раздел клиентов.

Там появится клиент:

`cascade`

Его параметры:

- протокол VLESS через существующий REALITY;
- `flow`: `xtls-rprx-vision`;
- клиент включён;
- лимит трафика не установлен;
- срок действия не ограничен;
- используется отдельный UUID, то есть уникальный идентификатор клиента.

Каскад не заменяет стандартное подключение REALITY и не удаляет других пользователей.

Подключение между серверами происходит по внешнему TCP-порту **443**, а не по внутреннему порту 8443, который использует управляемый REALITY.

## 5. Подключаем российский VPS к зарубежному

Теперь перейди на российский, то есть входной сервер. Если вошёл не под root, сначала выполни `sudo -i`.

**На российском VPS от root** открой менеджер 3X-UI AUTO NGINX:

```bash
bash x-ui-latest.sh
```

Выбери:

**5. Каскад → 2. Подключить выходной сервер (входной сервер)**

Менеджер снова запросит логин и пароль, но на этот раз от панели **российского VPS**.

После авторизации он проверит состояние Xray, существующие правила маршрутизации и возможные конфликты.

Если всё в порядке, появится приглашение вставить ключ-ссылку выходного сервера.

Вставь `vless://` ссылку, скопированную на предыдущем этапе.

Обрати внимание: при вставке ссылка будет видна в терминале. Не записывай экран и не публикуй скриншот с ключом.

Менеджер проверит возможность соединения с зарубежным сервером. Если соединение успешно, он добавит настройки каскада в Xray и проверит их.

При успешном завершении появится сообщение:

`Каскад подключён.`

**При применении изменений Xray может перезапуститься, а действующие пользовательские соединения ненадолго прерваться.**

Если проверка не пройдёт, менеджер попытается удалить внесённые изменения. Результат отката будет показан отдельно. Не считай откат успешным, если менеджер не смог его подтвердить.

## 6. Что именно создаёт каскад в 3X-UI

На входном сервере открой панель управления 3X-UI.

### Исходящее подключение

В разделе **Xray → Исходящие (Outbounds)** появится:

`cascade-exit`

Это VLESS-подключение с REALITY к зарубежному серверу.

Оно содержит настройки из полученной ключ-ссылки, включая адрес, порт, UUID и параметры REALITY.

Его задача - передавать подходящий трафик с российского VPS на зарубежный.

Это не новое входящее подключение для твоего телефона. Клиентские приложения продолжат использовать прежние профили российского сервера.

### Правила маршрутизации

В разделе **Xray → Маршрутизация (Routing)** появятся три правила.

| Правило | Условие | Действие |
|---|---|---|
| `CASCADE - RU` | `geosite:category-ru` | `direct` |
| `CASCADE - RU2` | `geoip:ru` | `direct` |
| `CASCADE - EXIT` | TCP и UDP | `cascade-exit` |

**CASCADE - RU** направляет российские домены непосредственно через входной VPS.

**CASCADE - RU2** аналогично обрабатывает соединения, для которых определён российский IP-адрес назначения.

**CASCADE - EXIT** направляет остальной подходящий трафик в `cascade-exit`, то есть на зарубежный VPS.

Правила добавляются в конец существующего списка. Xray обрабатывает их по порядку, поэтому более ранние правила могут перехватывать часть трафика.

Например, если выше каскада есть пользовательское правило для YouTube с другим выходом, оно сохранит свой приоритет.

Стандартные правила панели для служебного API, локальных адресов и BitTorrent также сохраняются.

### Что не изменяется

После включения каскада:

- существующие клиенты не удаляются;
- их UUID и ссылки подписок не меняются;
- новые клиентские профили на входном VPS не требуются;
- стандартные входящие подключения REALITY, XHTTP и Hysteria2 сохраняются;
- домены и HTTPS-сертификаты не заменяются.

В результате пользователи продолжают подключаться привычным способом, а выбор дальнейшего маршрута выполняет Xray на входном сервере.

## 7. Проверяем, что каскад работает {#cascade-verify}

Проверку проведи в три этапа: состояние, выходной IP и российские сайты.

### Шаг 1. Проверь состояние в менеджере

На зарубежном VPS открой:

**5. Каскад → 3. Состояние**

Выходная роль должна быть готова, а клиент `cascade` включён.

На российском VPS открой тот же пункт:

**5. Каскад → 3. Состояние**

Входная роль должна отображаться как настроенная, а Xray - работающим.

Проверка состояния ничего не меняет в конфигурации.

Но она подтверждает прежде всего наличие настроек. Чтобы проверить реальную передачу пользовательского трафика, нужен следующий шаг.

### Шаг 2. Проверь подключение с устройства

На телефоне, компьютере или роутере:

1. Подключись к обычному профилю российского VPS.
2. Убедись, что приложение действительно направляет проверочный трафик через прокси.
3. Открой [ipify.org](https://www.ipify.org/) или [ifconfig.me](https://ifconfig.me/).
4. Сравни показанный IP-адрес с публичным IP зарубежного VPS.

Для обычного прямого выхода через каскад должен отображаться адрес зарубежного сервера.

Если показывается российский IP, проверь правила маршрутизации и режим работы клиентского приложения. Возможна ситуация, когда запрос идёт напрямую или обрабатывается другим правилом.

Если на выходном VPS используется WARP, отдельные запросы могут выходить через Cloudflare. Это нужно учитывать при проверке.

### Шаг 3. Проверь российские сайты

Открой несколько российских сервисов, которые обычно используешь.

По умолчанию маршруты `geosite:category-ru` и `geoip:ru` отправляют подходящий трафик напрямую с российского VPS.

Это уменьшает необходимость отправлять российский трафик за границу и обратно.

При этом определение страны зависит от правил и баз geosite/geoip, поэтому конкретный сайт не обязательно будет классифицирован так, как ожидается.

## Необязательно: отправлять российский трафик через зарубежный VPS

Да, можно изменить маршрут российских сайтов.

Для этого в панели входного VPS открой **Xray → Маршрутизация** и отключи правила:

- `CASCADE - RU`
- `CASCADE - RU2`

Правило `CASCADE - EXIT` оставь включённым. Нажми общее «Сохранить» на основной странице Xray и повтори проверку с устройства. Если результат не подходит, снова включи оба российских правила и сохрани конфигурацию.

Тогда трафик, который не обработали более ранние правила, будет направляться через выходной VPS.

Это необязательная настройка. Для первого запуска рекомендуется оставить стандартную маршрутизацию.

## 8. Частые ошибки и их решение

### WARP уже установлен на российском VPS {#cascade-remove-warp}

Это один из самых распространённых конфликтов.

При попытке подключения менеджер обнаруживает WARP и отказывается изменять настройки каскада.

Причина в том, что WARP и каскад создают правила маршрутизации, влияющие на выбор выходного подключения.

**Как исправить:**

Сначала сохрани [Backup](backup.md) вне VPS. Изменение маршрутизации может кратковременно прервать подключения. Удаляй только перечисленные настройки WARP, не другие исходящие или пользовательские правила.

1. Открой панель российского VPS.
2. Перейди в **Xray → Маршрутизация**.
3. Найди принадлежащие WARP правила `WARP - RU`, `WARP - RU2`, `WARP - RU3`.
4. Удали эти правила.
5. Перейди в **Xray → Исходящие (Outbounds)**.
6. Удали исходящее подключение `warp-masque`.
7. Нажми общее «Сохранить» на основной странице Xray. Проверь, что Xray работает и обычное подключение сохранилось.
8. Если выполняешь подготовку впервые, вернись к [проверке готовности обоих VPS](#cascade-existing-both). Если ключ выходного VPS уже получен, повтори подключение каскада через менеджер.

Простого выключения правил WARP недостаточно: менеджер обнаруживает даже отключённые правила с этими названиями.

На зарубежном выходном VPS WARP использовать можно.

### Не удалось подключиться к выходному серверу

Если менеджер сообщил, что проверка соединения не прошла, возможные причины:

- зарубежный VPS недоступен из сети российского;
- на выходном сервере не работает Xray;
- закрыт внешний TCP-порт 443;
- ключ-ссылка скопирована не полностью;
- изменились домены или параметры REALITY;
- соединение между VPS блокируется или прерывается.

Сначала убедись, что веб-панель зарубежного сервера открывается и Xray работает.

На российском VPS с правами root можно проверить доступность TCP-порта:

```bash
timeout 5 bash -c 'echo > /dev/tcp/ИМЯ_ДОМЕНА/443' && echo "TCP 443 доступен"
```

Заменяй `ИМЯ_ДОМЕНА` доменом REALITY выходного VPS.

При успешном подключении появится `TCP 443 доступен`. При ошибке команда завершится без этого сообщения.

Этот тест проверяет только возможность установить TCP-соединение. Он не подтверждает корректность REALITY, ключа или самого каскада.

Если TCP работает, попробуй получить новую ссылку на выходном VPS и повторить настройку. Используй именно ссылку, которую выдаёт пункт создания ключа, а не обычную пользовательскую подписку.

### Клиент cascade уже существует

На зарубежном сервере менеджер может сообщить, что клиент с именем `cascade` уже существует.

Повторно создать клиента с тем же именем нельзя.

Открой раздел клиентов в панели 3X-UI и проверь существующую запись.

Если это клиент ранее настроенного каскада, сначала проверь **5. Каскад → 3. Состояние**. Не удаляй его без необходимости: другие входные серверы могут уже использовать этот ключ.

Если имя занято твоим собственным клиентом, не относящимся к каскаду, переименуй его и повтори создание ключа.

### Менеджер обнаружил существующие правила маршрутизации

Каскад добавляет свои правила в конец списка. Если над ними находятся пользовательские правила, они могут изменить ожидаемый маршрут.

Менеджер предупредит об этом.

Открой **Xray → Маршрутизация** и проверь правила с указанными номерами.

Если правило направляет весь TCP-трафик в другой выход, оно может сделать каскад бесполезным. В таком случае менеджер откажется от подключения.

Исправь или отключи конфликтующее правило, если оно тебе больше не нужно.

Стандартные правила панели удалять не следует.

### Каскад уже подключён

Если входная роль уже настроена или настроена частично, повторное подключение без предварительного отключения не выполняется.

Сначала открой **5. Каскад → 3. Состояние**.

Если требуется заменить зарубежный VPS, воспользуйся пунктом **4. Отключить** на входном сервере и после подтверждения подключи новый выход.

### После подключения перестал работать Xray

Это может происходить при ошибках конфигурации или применении новых правил.

Менеджер проверяет состояние Xray и маршруты после сохранения. Если проверки не пройдут, он пытается откатить изменения.

Открой панель и проверь состояние Xray.

Если менеджер сообщил о неподтверждённом откате, дополнительно проверь:

- исходящее подключение `cascade-exit`;
- правила `CASCADE - RU`, `CASCADE - RU2`, `CASCADE - EXIT`;
- оставшиеся пользовательские правила.

Не повторяй подключение вслепую, пока не выяснено фактическое состояние конфигурации.

### Каскад перестал работать после смены доменов

Если на зарубежном VPS выполнить **2. Смена доменов**, параметры подключения REALITY могут измениться.

Старая ключ-ссылка перестанет соответствовать настройкам выходного сервера.

В этом случае:

1. Проверь состояние выходной роли.
2. На входном VPS отключи прежний каскад через меню.
3. На выходном VPS получи новую актуальную ключ-ссылку. При необходимости пересоздай выходную роль штатными пунктами меню.
4. Повтори подключение на входном VPS.

Не меняй UUID, REALITY-ключи и другие параметры вручную ради восстановления старой ссылки.

### Некоторые приложения не работают через каскад

Каскад использует VLESS REALITY с Vision для соединения между серверами.

Есть ограничение: **QUIC-трафик через UDP/443 не проходит через такой каскад**. Это может влиять на приложения и сайты, использующие HTTP/3.

Кроме того, AmneziaWG-подключения в текущей реализации не направляются через выходной сервер.

Если приложение работает напрямую, но не работает через каскад, проверь, какой транспорт оно использует. Для отдельных сервисов может потребоваться другой клиентский профиль или маршрут.

### Зарубежный VPS временно недоступен

Если выходной сервер отключён, перегружен или соединение между VPS блокируется, трафик, направленный через него, перестанет проходить.

Встроенный каскад не создаёт автоматический резервный зарубежный выход.

При этом соединения, для которых настроен прямой маршрут через российский VPS, могут продолжать работать.

Для восстановления нужно вернуть доступность выходного сервера либо перенастроить входной VPS на другой выход.

## 9. Как отключить каскад

Если каскад больше не нужен, его можно удалить через штатное меню.

Рекомендуемый порядок: сначала отключить входной сервер, затем при необходимости удалить клиента на выходном.

### На российском VPS

Открой:

**5. Каскад → 4. Отключить**

Менеджер предложит удалить:

- исходящее подключение `cascade-exit`;
- правила `CASCADE - RU`, `CASCADE - RU2`, `CASCADE - EXIT`.

После подтверждения эти элементы будут удалены. Другие исходящие подключения, стандартные правила и пользовательские профили сохранятся.

Клиентские подключения продолжат существовать, но их маршрутизация изменится. Поэтому после отключения проверь доступ к интернету.

### На зарубежном VPS

Открой тот же пункт:

**5. Каскад → 4. Отключить**

Здесь будет предложено удалить клиента `cascade`.

Помни: если один выходной VPS используется несколькими входными серверами с общим ключом, удаление этого клиента разорвёт их межсерверные подключения.

Каждое удаление требует отдельного подтверждения.

## 10. Резервные копии и перенос серверов

Настройки каскада сохраняются в Backup v3 вместе с конфигурацией 3X-UI.

Но после восстановления на другом VPS нужно проверить не только наличие правил, но и доступность выходного сервера.

Если менялись домены, IP-адреса или REALITY-параметры, межсерверное подключение может потребовать повторной настройки.

Храни резервные копии за пределами VPS.

Важно различать две операции:

- **Backup / Restore** восстанавливает данные установленного стека.
- **Восстановление клиентов и подписок** переносит клиентов на новую установку, но не заменяет всю конфигурацию маршрутизации нового VPS.

Поэтому после переезда на новый сервер обязательно проверь каскад в меню **5. Каскад → 3. Состояние** и отдельно проверь реальную работу подключения с устройства.
