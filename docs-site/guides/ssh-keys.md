# SSH-ключи для Ubuntu 24.04 и 26.04

SSH (Secure Shell) позволяет управлять VPS через защищённое соединение. Для входа на сервер мы рекомендуем использовать SSH-ключ вместо пароля учётной записи.

## Почему лучше использовать SSH-ключ

Пара SSH-ключей состоит из двух частей: **закрытый ключ** хранится на твоём устройстве, а **открытый (публичный) ключ** добавляется на VPS. При входе SSH-клиент доказывает серверу, что у него есть закрытый ключ, не передавая его по сети.

- **Защита от подбора:** современный ключ Ed25519 практически невозможно подобрать перебором. Если отключить парольный вход после проверки ключа, автоматический подбор пароля больше не позволит войти по SSH.
- **Удобство:** не нужно каждый раз вводить пароль учётной записи VPS. Один ключ можно добавить на несколько своих серверов.
- **Контроль доступа:** можно создать отдельные ключи для компьютера и телефона. Если потеряешь устройство, достаточно удалить его открытый ключ с серверов.

Парольная фраза защищает сам закрытый ключ и отличается от пароля учётной записи VPS. Рекомендуем её установить. Закрытый ключ нельзя отправлять на сервер, публиковать или передавать другим людям.

## Подготовка: под каким пользователем подключаться

Для управления 3X-UI AUTO NGINX нужен `root` - администратор Linux с полным доступом к системе. Обычно для SSH-подключения используется имя `root`.

Если хостер запретил прямой вход root, используй выданную им учётную запись (например, `ubuntu`). **Добавляй и проверяй ключ именно для этой учётной записи.** После успешного входа по ключу получишь права root командой `sudo -i`, как описано ниже. Менять настройки SSH ради разрешения прямого входа root не нужно.

Выбери один из двух способов. Выполнять оба не требуется.

- [Способ 1. Termius (рекомендуем)](#method-termius) - создание и отправка ключа через приложение.
- [Способ 2. PowerShell в Windows 11](#method-powershell) - встроенные команды Windows, без дополнительных приложений.

После любого способа перейди к [общей проверке и дальнейшей работе](#ssh-key-check).

!!! warning "Не потеряй доступ к VPS"
    Сначала убедись, что можешь войти на сервер существующим способом. Оставь это SSH-подключение открытым до проверки нового входа. Если хостер предоставляет консоль VPS в личном кабинете, убедись, что она доступна.

## Способ 1. Termius (рекомендуем) {#method-termius}

[Termius](https://termius.com/) - SSH-клиент для Windows, macOS, Linux, iOS и Android. Он удобен тем, что хранит список серверов и ключи в одном приложении, позволяет подключаться в пару нажатий и передавать файлы через SFTP. Создать ключ и добавить его на сервер можно без команд в терминале.

Для этой задачи достаточно бесплатного тарифа Starter. Его основной недостаток - хранилище локальное, автоматической синхронизации серверов и ключей между устройствами нет. Синхронизация доступна на платных тарифах. [Сравнение тарифов](https://termius.com/pricing).

### 1. Добавь сервер и проверь вход

1. Установи Termius с [официального сайта](https://termius.com/download/windows) или из магазина приложений на телефоне.
2. Открой **Hosts → New Host** и укажи IP-адрес VPS, имя пользователя `root`, порт SSH (обычно 22) и пароль, выданный хостером. Если прямой вход root запрещён, укажи своего пользователя вместо `root`.
3. Сохрани сервер и подключись. При первом подключении сверяй отпечаток ключа сервера с данными хостера или консоли VPS, если он доступен. Не принимай неожиданное изменение отпечатка без проверки.
4. Убедись, что терминал открылся, и оставь это подключение открытым.

### 2. Создай ключ

1. Открой **Keychain** (хранилище ключей).
2. Выбери **New key → Generate key**. На телефоне создание ключа может открываться через кнопку `+`.
3. В поле **Label** укажи понятное название, например «Мой ноутбук».
4. В поле **Key type** выбери **Ed25519**.
5. Задай **Passphrase** (парольную фразу закрытого ключа) и сохрани её в менеджере паролей.
6. Нажми **Generate & save**.

Если у тебя уже есть SSH-ключ, вместо создания нового можешь импортировать его в Keychain через **Import from key file**. Выбирай закрытый файл ключа только на своём устройстве, не отправляй его на VPS.

### 3. Отправь открытый ключ на VPS

1. В **Keychain** открой меню созданного ключа (на компьютере - правой кнопкой мыши) и выбери **Export to host**. На телефоне эта команда может находиться в меню **Share** после долгого нажатия на ключ.
2. Нажми **Select Host** и выбери добавленный VPS. Подтверди экспорт. При необходимости введи пароль учётной записи сервера.
3. Termius подключится к VPS и добавит публичную часть ключа в `~/.ssh/authorized_keys` выбранного пользователя. Закрытая часть останется в приложении.
4. В настройках карточки сервера проверь, что созданный ключ выбран в поле **Key** (в некоторых версиях через **SSH ID → Key**).

### 4. Проверь вход по ключу

Не закрывая старый сеанс, убери сохранённый пароль учётной записи из карточки сервера (сохрани его отдельно) и открой новое SSH-подключение с выбранным ключом. Если Termius запрашивает пароль VPS, не вводи его для этой проверки: сначала проверь экспорт и привязку ключа. Запрос парольной фразы самого ключа допустим.

При успехе откроется терминал VPS без ввода пароля учётной записи. Перейди к общему разделу проверки ниже.

## Способ 2. PowerShell в Windows 11 {#method-powershell}

Этот способ использует встроенный SSH-клиент Windows и не требует установки Termius.

### 1. Проверь обычный вход

**На своём компьютере, в PowerShell:**

```powershell
ssh root@IP_ТВОЕГО_VPS
```

Здесь и далее подставляй адрес своего VPS. Если хостер выдал другую учётную запись, замени `root` на неё (например, `ubuntu`). Если SSH использует нестандартный порт, добавь к командам подключения параметр `-p ПОРТ` после `ssh`.

Оставь первое SSH-подключение открытым.

### 2. Создай пару ключей на своём ПК

**Открой второй PowerShell на своём компьютере** (не терминал VPS) и проверь, существует ли уже ключ:

```powershell
Test-Path "$env:USERPROFILE\.ssh\id_ed25519"
```

Если ответ `True`, ключ уже есть. Используй его и соответствующий публичный файл `.pub`, если они доступны, или выбери другое имя для новой пары. **Не перезаписывай существующий ключ**: он может открывать доступ к другим серверам.

Если ответ `False`, подготовь каталог и создай новую пару:

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.ssh" | Out-Null
ssh-keygen -t ed25519 -a 64 -f "$env:USERPROFILE\.ssh\id_ed25519"
```

Программа попросит придумать парольную фразу закрытого ключа. Рекомендуем задать её и сохранить в менеджере паролей. После создания появятся два файла:

- `id_ed25519` - закрытый ключ. Не отправляй его на сервер.
- `id_ed25519.pub` - открытый ключ, который можно добавлять на VPS.

### 3. Добавь открытый ключ на VPS

**На своём ПК, в PowerShell:**

```powershell
Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub" | ssh root@IP_ТВОЕГО_VPS "umask 077; mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"
```

Если входишь не под root, укажи того же пользователя, под которым подключался на первом шаге. При другом имени файла ключа или порте SSH также замени соответствующие значения.

Команда передаёт только публичную часть ключа через SSH, создаёт каталог `~/.ssh` и дописывает ключ в `authorized_keys`. Уже сохранённые ключи не удаляются. Права `700` на каталог и `600` на файл ограничивают доступ других обычных пользователей. Если команда завершилась без ошибки, повторять её не нужно: иначе появится дубликат ключа.

### 4. Проверь отдельное подключение по ключу {#powershell-key-check}

**На ПК открой ещё один PowerShell:**

```powershell
ssh -o ControlPath=none -o IdentitiesOnly=yes -o PreferredAuthentications=publickey -o PasswordAuthentication=no -o KbdInteractiveAuthentication=no -i "$env:USERPROFILE\.ssh\id_ed25519" root@IP_ТВОЕГО_VPS
```

Подставь свои значения пользователя, адреса, порта и файла ключа. Команда проверяет вход только по ключу, без перехода к парольной аутентификации. При успехе откроется терминал Ubuntu. Может потребоваться парольная фраза ключа, но не пароль VPS.

## Общая проверка и дальнейшая работа {#ssh-key-check}

Если новый вход по ключу прошёл, проверь имя пользователя командой `whoami`. Если вход не удался, не закрывай исходный сеанс. Проверь адрес VPS, пользователя, выбранный ключ и права на его каталог `~/.ssh` (700) и файл `authorized_keys` (600).

### Получи права root для работы с проектом

Если `whoami` уже показал `root`, ничего дополнительно делать не нужно. Если хостер выдаёт вход через обычного пользователя с правами sudo, выполни **на VPS**:

```bash
sudo -i
```

Проверь:

```bash
whoami
```

Должно появиться `root`. Теперь можно запускать установщик и выполнять серверные команды из [инструкции первого запуска](../start.md). При следующем подключении под обычным пользователем повтори `sudo -i`.

### Что делать с паролем SSH

Наш установщик **не отключает вход по паролю**, чтобы не лишить тебя доступа к VPS. Пока сервер принимает парольный вход, возможность его подбора сохраняется, даже если ты сам пользуешься ключом.

**После проверки входа по ключу со всех нужных устройств рекомендуем отключить вход по паролю.** В отдельном руководстве показаны ручная настройка и готовый скрипт, а также проверка результата и безопасный откат. Не закрывай рабочий SSH-сеанс до завершения проверки.

[Отключить вход по паролю через SSH](ssh-password.md){ .md-button .md-button--primary }

Сохрани закрытый ключ в защищённой резервной копии. Бесплатное локальное хранилище Termius не заменяет резервную копию: потеря устройства или переустановка приложения может лишить тебя ключа.

### Как удалить добавленный ключ

Если нужно отменить настройку, используй оставшееся SSH-подключение или другой рабочий способ доступа. **От имени пользователя, которому добавлял ключ,** открой:

```bash
nano ~/.ssh/authorized_keys
```

Удали только строку с нужным публичным ключом и сохрани файл. Другие ключи и настройки SSH оставь без изменений. Перед удалением убедись, что у тебя останется рабочий способ входа.
