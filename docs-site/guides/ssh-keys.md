# SSH-ключи для Ubuntu 24.04 и 26.04

SSH (Secure Shell) позволяет управлять VPS через защищённое соединение. Вместо пароля сервера можно использовать **пару ключей**: закрытый ключ остаётся на твоём компьютере, а открытый добавляется на сервер. При подключении сервер проверяет ключ и разрешает вход.

Эта инструкция подходит для Ubuntu 24.04 LTS и 26.04 LTS. В примерах компьютер работает под Windows 11, сервер принимает соединения под пользователем `ubuntu` или `root`.

## 1. Сначала проверь обычный вход

**На своём компьютере, в PowerShell Windows 11:**

```powershell
ssh ubuntu@IP_ТВОЕГО_VPS
```

Здесь и далее подставляй адрес своего VPS. Если хостер выдал вход `root`, замени `ubuntu` на `root`. Если SSH использует нестандартный порт, добавь к командам подключения параметр `-p ПОРТ`.

После входа выполни на VPS:

```bash
whoami
```

Команда покажет пользователя, для которого ты будешь добавлять ключ. **Оставь первое SSH-подключение открытым** до конца настройки.

## 2. Создай пару ключей на своём ПК

**Открой второй PowerShell на своём компьютере** (не терминал VPS) и проверь, не существует ли уже обычный ключ:

```powershell
Test-Path "$env:USERPROFILE\.ssh\id_ed25519"
```

Если ответ `True`, ключ уже есть. Используй его и переходи к шагу 3. **Не перезаписывай существующий ключ**: он может открывать доступ к другим серверам.

Если ответ `False`, подготовь каталог и создай новую пару:

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.ssh" | Out-Null
ssh-keygen -t ed25519 -a 64 -f "$env:USERPROFILE\.ssh\id_ed25519"
```

Программа попросит придумать парольную фразу для закрытого ключа. Рекомендую задать её и сохранить в менеджере паролей. После создания появятся два файла:

- `id_ed25519` - закрытый ключ. **Не отправляй его на сервер и никому не передавай.**
- `id_ed25519.pub` - открытый ключ, который можно добавлять на VPS.

## 3. Добавь открытый ключ на VPS

**На своём ПК, в PowerShell:**

```powershell
Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub" | ssh ubuntu@IP_ТВОЕГО_VPS "umask 077; mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"
```

При необходимости замени `ubuntu` на `root`, а для нестандартного SSH-порта вставь `-p ПОРТ` после `ssh`.

Что делает команда: передаёт **только публичную часть ключа** через SSH, создаёт папку `~/.ssh` и дописывает ключ в `authorized_keys`. Уже сохранённые ключи не удаляются. Права `700` на каталог и `600` на файл не позволяют другим обычным пользователям читать эти данные.

Если команда завершилась без ошибки, ключ добавлен. Повторять её не нужно: иначе в файле появится дубликат.

## 4. Проверь отдельное подключение по ключу

**На ПК открой ещё один PowerShell** и выполни:

```powershell
ssh -o PreferredAuthentications=publickey -o PasswordAuthentication=no -i "$env:USERPROFILE\.ssh\id_ed25519" ubuntu@IP_ТВОЕГО_VPS
```

Здесь тоже подставь своё имя пользователя и, если требуется, `-p ПОРТ`. При успешном подключении появится оболочка Ubuntu. Может потребоваться **парольная фраза ключа**, но не пароль учётной записи VPS.

На сервере проверь:

```bash
whoami
ls -ld ~/.ssh
ls -l ~/.ssh/authorized_keys
```

Должен отображаться нужный пользователь и права `drwx------` для `~/.ssh`, `-rw-------` для `authorized_keys`.

Если проверка завершилась ошибкой `Permission denied (publickey)`, не закрывай исходную SSH-сессию. Проверь имя пользователя, адрес сервера и содержимое `~/.ssh/authorized_keys` именно этого пользователя.

## 5. Что делать дальше

Теперь ключ можно выбрать в своём SSH-клиенте, например Termius, или использовать стандартную команду `ssh`. Сохрани закрытый ключ в защищённой резервной копии: если он пропадёт, без другого способа входа восстановить доступ будет сложно.

Наш установщик **не отключает вход по паролю**, чтобы случайно не лишить тебя доступа к VPS. Когда вход по ключу проверен, ты можешь отдельно настроить запрет парольной аутентификации. Для этого полезна [официальная документация Ubuntu по OpenSSH](https://ubuntu.com/server/docs/how-to/security/openssh/). Изменение `sshd_config` требует отдельной проверки настроек и нового входа до закрытия старого сеанса; эта статья безопасно ограничивается добавлением ключа.

**Как откатить добавление:** войди через оставшееся SSH-подключение и от имени нужного пользователя открой файл:

```bash
nano ~/.ssh/authorized_keys
```

Удали **только добавленную строку** с публичным ключом и сохрани файл. Другие ключи и настройки SSH оставь без изменений.
