# Первый запуск: от чистого VPS до первого подключения

Это самостоятельная инструкция для новичка. Ты подготовишь сервер и домены, установишь 3X-UI AUTO NGINX, разберёшься с семью вопросами установщика и проверишь подключение. Не нужно заранее уметь настраивать nginx или Xray.

## 1. Что подготовить

- **Чистый VPS** с Ubuntu 24.04 LTS, Ubuntu 26.04 LTS или Debian 13. VPS (Virtual Private Server) - виртуальный сервер, который ты арендуешь у хостинг-провайдера.
- **Доступ по SSH** - удалённый терминал. Нужен вход от `root` или пользователь с правом выполнять `sudo`.
- **Два разных домена или поддомена**: для панели и подписок, а также для REALITY.
- **Доступные из интернета порты** TCP 80 и 443, UDP 443. Некоторые хостеры требуют открыть их дополнительно в своей панели. TCP 853 понадобится только при включении DoT для устройств.

!!! tip "Какую операционную систему выбрать?"
    Новичку подойдёт **Ubuntu 24.04 LTS**, поскольку у неё длительная поддержка и много документации. Ubuntu 26.04 LTS и Debian 13 тоже поддерживаются. Рекомендую начинать с действительно чистой ОС, на которой ещё нет стороннего nginx, 3x-ui и других веб-сервисов.

### Настрой домены

Например, у тебя есть `example.com`:

| Для чего нужен | Поддомен | DNS-запись |
| --- | --- | --- |
| Панель, подписки и HTTPS | `panel.example.com` | A → IPv4 твоего VPS |
| Подключение REALITY | `reality.example.com` | A → тот же IPv4 |

Имена вымышленные, замени их собственными. **A-запись** сопоставляет домен с IPv4-адресом. Если у домена есть **AAAA-записи** для IPv6, они должны указывать на работающий IPv6 этого же VPS. Иначе часть устройств будет попадать на неправильный адрес.

Подожди, пока домены начнут разрешаться в правильный IP. Установщик получает сертификаты автоматически, но для этого домен панели должен быть доступен, а TCP 80 открыт извне.

## 2. Подключись по SSH

**На своём компьютере** открой терминал или SSH-клиент. Например, в PowerShell на Windows 11 выполни:

```bash
ssh root@IP_ТВОЕГО_VPS
```

Заменяй `IP_ТВОЕГО_VPS` адресом, выданным хостером. Если хостер создал пользователя `ubuntu`, подключайся под ним:

```bash
ssh ubuntu@IP_ТВОЕГО_VPS
```

Уже **на сервере** получи права администратора:

```bash
sudo -i
```

После успеха терминал будет работать с правами `root`. Следующие команды выполняются **на VPS**, а не на твоём компьютере.

**Хочешь безопаснее входить на сервер без пароля учётной записи?** Мы подготовили отдельную инструкцию по [добавлению SSH-ключей в Ubuntu 24.04 и 26.04](guides/ssh-keys.md). В ней показаны команды для Windows 11, проверка отдельного подключения и безопасный откат.

!!! danger "Переустановка удаляет управляемые данные"
    Скачивание и запуск менеджера сами по себе ничего не переустанавливают. Но пункт **«1. Установка»** на уже настроенном VPS после подтверждения заменяет базу 3x-ui и конфигурацию nginx. **Не используй установку для обновления.** Если VPS не новый, заранее сохрани Backup **вне VPS** и используй отдельные пункты управления сервером.

## 3. Скачай и открой установщик

**На чистом VPS от root**:

```bash
curl -fSL https://github.com/xPROMSx/3x-ui-auto-nginx/releases/latest/download/x-ui-latest.sh -o x-ui-latest.sh && bash x-ui-latest.sh
```

Команда скачивает скрипт **последнего стабильного релиза**, затем запускает его. Если загрузка не удалась, установка не начнётся.

В интерактивном меню выбери **2 - Русский**, затем **1 - Установка**. Не закрывай SSH-сеанс до завершения.

## 4. Отвечай на вопросы установщика

Установщик задаст семь основных вопросов. Для обычного первого сервера рекомендую следующие ответы:

| Вопрос | Рекомендация | Почему |
| --- | --- | --- |
| **1. Домен панели** | `panel.example.com` | Здесь работают панель, подписки и сайт-прикрытие |
| **2. Домен REALITY** | `reality.example.com` | Отдельное имя для подключения REALITY |
| **3. Усилить безопасность VPS?** | **Y** | Fail2ban, шифрованный DNS сервера и автоматические обновления безопасности |
| **4. Дополнительные подключения?** | **N** | REALITY, XHTTP и Hysteria2 создаются и без них |
| **5. Скрыть IP через WARP?** | **Y** на одиночном VPS, **N** на входном сервере каскада | Выбранные российские сайты будут видеть адрес Cloudflare |
| **6. Установить AdGuard Home?** | **N**, если не нужен личный DNS | Не требуется для работы прокси |
| **7. Создать клиента и подписку?** | **Y** | Сразу получишь ссылку для подключения телефона или компьютера |

### 3. Почему рекомендуется усилить безопасность VPS

**Рекомендация: Y.** Дополнительная защита особенно полезна, если это твой первый сервер.

- **Fail2ban** временно блокирует источники множества неудачных SSH-входов. Установщик не отключает вход по паролю и не заменяет SSH-ключи. Позже можно самостоятельно настроить вход по ключам и отключить пароль после проверки.
- **DNS-over-TLS (DoT) самого VPS** шифрует глобальные DNS-запросы сервера через Cloudflare и Google. Это **не** DNS-сервер для твоих устройств. Запросы отдельных интерфейсов могут использовать свои DNS-настройки.
- **Обновления безопасности** выполняются автоматически. По локальному времени VPS: обновление списков пакетов в **02:30**, установка обновлений в **02:50**. Если нужна перезагрузка, она может выполняться в **04:38 даже при активных пользовательских подключениях**.

Так система сама получает исправления nginx, ядра Linux и других пакетов безопасности. Расписание приведено заранее, чтобы ты знал о возможных ночных перезагрузках.

[Подробно о защите VPS и примерах обновлений](guides/security.md).

**Swap** - использование части диска как дополнительной памяти при нехватке ОЗУ. Если нет действующего swap, файловая система подходит и хватает места, установщик может создать swap-файл размером 1 ГиБ. Это **не зависит** от ответа на вопрос безопасности.

### 4. Какие дополнительные подключения выбирать

**Рекомендация: N** для первой установки. REALITY, XHTTP и Hysteria2 уже создаются по умолчанию.

При ответе `Y` появятся отдельные вопросы о WebSocket/Trojan gRPC, XTLS Vision, AmneziaWG и дополнительном XHTTP для CDN. Например, **XTLS Vision требует третий домен**, а CDN-профиль потом нужно настраивать у CDN-провайдера. Нет необходимости включать всё сразу.

### 5. Cloudflare WARP: когда Y, а когда N

**Обычный одиночный VPS:** в русском меню по умолчанию `Y`. При успешной настройке выбранные правилами Xray российские сайты и сервисы будут видеть IP Cloudflare вместо IP твоего VPS. Это позволяет не раскрывать прямой адрес VPS этим назначениям.

WARP **не скрывает адрес от всех сайтов**, не является системным VPN и не влияет на трафик устройства, который вообще не отправлялся через прокси. При включении установщик регистрирует устройство в Cloudflare и принимает условия сервиса. Если Cloudflare недоступен, настройка WARP может завершиться частично.

!!! warning "Особый случай: входной сервер каскада"
    Если VPS будет **входным** сервером цепочки из двух VPS, **выбирай N**. WARP на этом сервере несовместим с каскадом из-за правил маршрутизации Xray. На **выходном** сервере WARP разрешён. [Подробное руководство по каскаду](guides/cascade.md).

### 6. Нужен ли AdGuard Home

**Рекомендация: N**, если тебе пока нужен только прокси. AdGuard Home - необязательный личный DNS-сервер для фильтрации рекламы и управления DNS-запросами устройств.

При `Y` появится панель AdGuard Home и персональный адрес DNS-over-HTTPS (DoH) на домене панели. Случайный путь затрудняет подбор, но не заменяет управление доступом: для разных устройств полезно настроить **ClientID** и список разрешённых клиентов.

Дополнительный **DoT для устройств** подходит, например, для функции «Частный DNS» Android. Он требует TCP 853, не передаёт ClientID, поэтому доступ к нему нельзя разграничить так же, как к DoH. Если он не нужен, оставь `N`. [Подробная инструкция по личному DNS и AdGuard Home](guides/dns.md).

### 7. Зачем создавать клиента сразу

**Рекомендация: Y.** Установщик создаст клиента в 3x-ui и покажет персональную HTTPS-ссылку подписки для совместимого приложения. Если выбрать `N`, клиентские учётные данные позже придётся создать вручную в панели.

## 5. Проверь результат

По завершении установщик показывает адрес панели, логин, пароль, отчёт о настройке компонентов и, если выбран клиент, ссылку подписки.

1. Сохрани данные панели и подписку в безопасном месте. **Не публикуй** пароли, ссылки и скриншоты с ними.
2. Открой панель в браузере и проверь, что Xray запущен.
3. Добавь ссылку подписки в поддерживаемое приложение на телефоне или компьютере.
4. Включи прокси в приложении и проверь доступ к сайтам. При проверке публичного IP убедись, что запрос действительно проходит через прокси.
5. Если установщик сообщил, что после обновления ОС требуется первоначальная перезагрузка, выполни её **на VPS от root** в подходящее время:

```bash
reboot
```

При успехе SSH-сеанс закроется, после запуска VPS к нему можно будет подключиться снова. Проверь панель и подключение повторно.

Если что-то не работает, сначала прочитай конкретную ошибку установщика, проверь DNS-записи и порты. **Не запускай «Установку» ещё раз вслепую.**

## 6. Управление уже установленным VPS

Повторный запуск менеджера без аргументов открывает меню. Для ежедневных задач есть другие пункты:

- **2 - Смена доменов**: [замена доменов панели и REALITY](guides/domains.md) без переустановки.
- **3 - Резервные копии**: [полный Backup / Restore и перенос клиентов](guides/backup.md) в новую установку.
- **5 - Каскад**: [пошаговая настройка двух VPS](guides/cascade.md).
- **6 - Данные моего сервера**: просмотр доступных адресов и сведений о сервере.

!!! warning "Установка не обновляет существующий стек"
    Поверх установленного стека 3X-UI AUTO NGINX автоматическое обновление не поддерживается. Системные пакеты, nginx и ядро Linux обновляются средствами ОС. Панель 3x-ui и Xray обновляй штатными средствами с учётом возможной несовместимости неподтверждённых версий.
