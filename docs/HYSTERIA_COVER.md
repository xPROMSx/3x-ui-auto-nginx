# Hysteria2: проверка HTTP/3-прикрытия

Проверено на официальных 3x-ui v3.11.0 / Xray 26.10.21, Nginx 1.24.0
и HTTP/3-клиенте aioquic 0.9.25 в одноразовом Ubuntu 24.04-контейнере.
Использованы настоящие TLS-соединения с проверкой тестового CA, нативная база
панели, её Xray-конфигурация и JSON-подписка. Публичный сайт — персонализированный
A1 из ресурсов проекта; HTTPS/TCP обслуживал действительный шаблон Nginx проекта.
Это локальная интеграционная проверка, а не проверка на production VPS или
измерение устойчивости к DPI/ТСПУ.

## Результат выбора

**Установщик пока не добавляет masquerade.** Ни один исследованный простой
вариант не выполнил все условия без изменения других контрактов. Hysteria2,
её авторизация, порты и существующие экспорты остаются прежними.

| Проверка | HTTPS/TCP | HTTP/3, `file` | HTTP/3, локальный Unix `proxy` |
| --- | --- | --- | --- |
| GET `/` | 200 | 200, тот же HTML | 200, тот же HTML |
| HEAD `/` | 200, без тела | 200, без тела | 200, без тела |
| POST `/` | 405 | **200** | 405 |
| GET `/index.html` | 200 | **301 на `./`** | 200 |
| Каталог `/product` | 301 на `/product/` | 301 на `product/` | 301 на `/product/` |
| GET `/product/` | 200 | 200 | 200 |
| GET `/static/` | 403 | **200 с листингом** | 403 |
| Неизвестный URL | 404, HTML | 404, простой текст | 404, тот же HTML |
| Неправильный Host | 404 | **200 с сайтом** | 404 |
| Страницы, CSS, JS, SVG, favicon | Доступны | Те же байты; есть отличия MIME/charset | Те же байты и MIME |
| Серверный путь в нативной JSON-подписке | Отсутствует без masquerade | **Появляется `dir`** | **Появляется Unix socket** |

`file` использует Go FileServer: листинг ресурсов, POST, Host и ответы об ошибках
не соответствуют управляемому HTTPS-сайту. Содержимое сайта не изменялось.
Этот режим не выбран.

Обычный `proxy` к существующему loopback HTTPS-listener возвращает **502**:
listener ожидает PROXY protocol перед TLS, а HTTP reverse proxy Xray его
не отправляет. Проверка сертификатов не отключалась.

`proxy` к собственному HTTPS-домену совпадает с TCP по проверенным ответам,
когда тестовое DNS/hosts явно направляет домен в loopback. Без такой привязки
он зависит от разрешения имени и маршрута к публичному адресу; отдельная
проверка без привязки не завершила HTTP/3-запрос. Это не гарантированно локальный
backend в существующей схеме.

Зависимость от DNS сама по себе не основание отвергать этот режим. Но отдельная
проверка настоящей панели подтвердила потерю адреса клиента: TCP- и QUIC-клиенты
привязаны к `127.0.0.2`, а failed-login в штатном `3xui.log` содержит соответственно
`127.0.0.2` и **`127.0.0.1`**. У HTTP/3-запроса были действительные CSRF cookie/token;
оба неверных входа действительно обработаны панелью. Даже `xForwarded=true`
не сохраняет адрес через текущую PROXY-цепочку Nginx, которая формирует свои
доверенные IP-заголовки. У всех таких клиентов возникает общий адрес для login
limiter. Режим не выбран: исправление потребовало бы изменения границы доверия
HTTP-заголовкам или отдельного backend, а не одного параметра masquerade.

Штатный Unix `proxy` работает без DNS и публичного дополнительного порта, но
требует отдельного статического Nginx-vhost. Все страницы и ресурсы обслуживаются
правильно. Административные и диагностические URL в этом статическом backend
возвращают 404; запрос с закодированным выходом из каталога получает 400 вместо
TCP 404. Главное препятствие — 3x-ui переносит серверный `masquerade` в нативную
JSON-подписку, раскрывая внутренний UDS-путь. Это противоречит действующему
контракту публичных экспортов. Исправление экспорта и сопровождение нового
управляемого vhost требуют отдельного решения; они не добавлены в этот PR.

## Авторизация и границы

В исследованных режимах нативная панель сохраняла masquerade в базе и передавала
его Xray. Настоящий Hysteria2-клиент передавал данные; неверные credentials
отклонялись. POST `/auth` с правильной Hysteria-авторизацией возвращал штатный
233, с неправильной — не 233. Неправильный SNI отвергался проверяющим сертификат
клиентом. Это не утверждение, что сервер отвергает произвольный SNI до проверки
сертификата клиентом.

Неавторизованные запросы к диагностике не выдавали `diag_key`. Проверенные пути
к базе, приватному ключу, `.env` и traversal не выдавали приватных файлов.
Листинг `file` раскрывал имена публичных ресурсов, поэтому считать его
приемлемым нельзя. Нет заявления об устранении всех сетевых отпечатков.

Поскольку masquerade не включена, прежние HTTP/3-отличия сохраняются: обычные
неавторизованные запросы получают стандартный ответ Hysteria2, а не Panel-сайт.
**Устранённых HTTP/3-отпечатков в этом PR нет.**

## Воспроизведение

`tests/hysteria_cover_probe.py` переиспользует `RealIntegration`: официальные
архивы проверяются существующими checksum/layout-проверками, процессы и база
создаются приватно и удаляются. Это ручной исследовательский инструмент,
не новый CI workflow и не замена обязательной integration suite.

В одноразовый Ubuntu 24.04-контейнер с зависимостями integration suite из
CONTRIBUTING.md добавить **только для эксперимента** пакет `python3-aioquic`.
Запускать от непривилегированного пользователя, с доступным локальным TCP/UDP 443,
не на установленном VPS. Внутри контейнера:

```bash
NGINX_BIN=/usr/sbin/nginx PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=tests \
  python3 tests/hysteria_cover_probe.py
```

По умолчанию проверяются отсутствие masquerade, `file`, loopback TLS proxy
и Unix proxy. `HY_EXPERIMENT_MODES` позволяет выбрать подмножество этих режимов.
Для дополнительного `proxy-own-domain` требуется тестовая hosts-запись
`127.0.0.1 deploy.example`; этот вариант намеренно не входит в запуск по умолчанию.
Он также проверяет IP в реальном файловом логе панели после TCP/HTTP3-запросов
с одного адреса `127.0.0.2`, без подмены сетевого обмена.
Вывод содержит только метаданные публичных ответов и булевы результаты,
без credentials, JSON-подписок, тел ответов и приватных логов.

## Рекомендация владельцу

До отдельного решения по безопасному экспорту masquerade предпочтительно сделать
Hysteria2 опциональной, если стандартная установка должна показывать одинаковый
сайт по TCP и UDP. Удалять её оснований нет: авторизованный транспорт работает.
В этом PR включение Hysteria2 по умолчанию **не изменено**. Автоматической
миграции, обновления действующих VPS или изменения Backup v3 не добавлено.

Отдельно для новых установок усилены `panel_path` и `xhttp_path` до 16 символов,
случайная часть `diag_path` до 16, пароль панели до 20. Остальные длины не менялись.
