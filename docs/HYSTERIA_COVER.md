# Hysteria2: Unix proxy и выбор публичного домена

Исследование PR #99 на официальных 3x-ui v3.11.0 / Xray 26.10.21,
Mihomo v1.19.32, Nginx 1.24.0 и aioquic 0.9.25 в одноразовом Ubuntu 24.04.
Архивы исполняемых файлов проверяет существующий `RealIntegration`.
Использованы настоящие TLS/QUIC, нативная база, нативные подписки и Xray панели.
Это не проверка production VPS, публичного ACME или устойчивости к ТСПУ.

## Вывод и текущий статус

**Unix proxy пригоден для статического HTTP/3-прикрытия.** Имя серверного сокета
в JSON не оказалось блокером: настоящий Xray принимает экспорт и передаёт TCP/UDP,
когда указанный сокет недоступен. Переписывание подписок или форк панели не нужны.
Предыдущий вывод о необходимости отвергнуть Unix proxy пересмотрен.

Рекомендован REALITY-домен с существующим `cover-reality`: его публичные TCP/UDP
ответы согласуются лучше, чем у Panel. Однако это меняет публичный адрес, SNI
и сертификат Hysteria2 для новых установок. **Привязка требует решения владельца
по п. 8 ТЗ; в исполняемый код она пока не внесена.** PR остаётся Draft.
Существующее усиление четырёх длин секретов сохранено.

[Минимальный diff установщика](HYSTERIA_REALITY_PROPOSAL.patch) — предложение,
а не применённая реализация. Ни старые VPS, ни их конфигурации не изменяются.

Подробное исследование Disable/Enable и резервного stream backend: см.
[независимость REALITY/Hysteria2](HYSTERIA_INDEPENDENCE.md). Оно уточняет
maintenance-health, сертификатные hooks и оставшиеся проверки reboot.

## Что проверено

Два ограниченных профиля, без повторения прежних file/DNS/loopback экспериментов:

| Профиль | Сайт | HTTP/1.1 ↔ HTTP/3 | HTTP/2 | Внутренние ссылки |
| --- | --- | --- | --- | --- |
| Panel Unix proxy | Существующий A1 / `cover-panel` | 83 случая | 6 случаев | 16 |
| REALITY Unix proxy | Существующий B1 / `cover-reality` | 93 случая | 6 случаев | 19 |

TCP/443 использует реальную конфигурацию проекта. Для REALITY запрос проходит
через stream router, настоящий Xray REALITY и HTTPS fallback с PROXY protocol.
HTTP/3 работает на UDP/443 через нативный Hysteria2 inbound панели.

Проверены GET/HEAD всех файлов и ссылок сайта, HTML/CSS/JS/SVG/favicon,
`/index.html`, POST `/`, каталоги с индексом и без него, редиректы без `/`,
неизвестные URL, регистр/порт Host, неправильный Host, `/auth`, панель,
диагностика, подписки, `.env`, пути к базе, ключу и сокету, encoded traversal.
HEAD не возвращает тело. Нет листинга, диагностической cookie или приватного
состояния в HTTP/3-ответах. Персонализированные файлы обоих сайтов не изменяются.

## Ответы и заголовки

| Запрос | TCP | HTTP/3 Unix proxy |
| --- | --- | --- |
| GET `/`, `/index.html`, страницы и ресурсы | 200 | 200, те же байты |
| HEAD `/` и ресурсы | 200, без тела | 200, без тела |
| POST `/` | 405 | 405 |
| Каталог с индексом без `/` | 301, относительный Location | То же |
| Каталог с индексом с `/` | 200 | 200 |
| Каталог без индекса `/static/` | 403 | 403 |
| Неизвестный URL | 404 | 404, тот же HTML |
| Неправильный Host | 404 | 404 |
| Encoded traversal | 404 | 400, приватные файлы недоступны |
| `/assets`, `/assets/` на Panel | 301/200 (HEAD также может дать 307) | 404 |
| `/assets`, `/assets/` на REALITY | 404 | 404 |
| Известная действующая подписка | 200 на обоих TCP-vhost | 404 |

Для публичных страниц и ресурсов совпадают Content-Type, Content-Length,
Cache-Control (включая отсутствие), ETag, Last-Modified, Location, Server
(`nginx`), Accept-Ranges и отсутствие Set-Cookie. Те же свойства проверены
на представительных HTTP/2-запросах. Имена HTTP/3-заголовков нормализуются;
Date, Connection и Transfer-Encoding не требуют буквального совпадения.
В неавторизованных ответах нет специальных заголовков Hysteria2.

Разница 400/404 для некорректного traversal допустима для обычных HTTP-серверов;
специальный фильтр ради неё не предлагается. Panel TCP также обслуживает панель,
SSO и диагностические маршруты, тогда как статический HTTP/3-vhost возвращает
404. REALITY не имеет этих Panel-маршрутов и корневых ресурсов 3x-ui `/assets`;
это его практическое преимущество. Публичные ссылки подписок по TCP остаются
доступны согласно существующему контракту, но не добавляются в HTTP/3-backend.

## SNI и авторизация

Предыдущий отказ TLS-клиента при неправильном SNI не доказывал отказ сервера.
Теперь отдельно проверен атакующий тестовый клиент, который намеренно не
проверяет сертификат. Без `rejectUnknownSni` сервер отвечает 200 при неправильном
SNI и правильном Host. С `tlsSettings.rejectUnknownSni=true` сам Xray отклоняет
неизвестное имя до HTTP, а правильные HTTP/3 и Hysteria2 продолжают работать.
Опция проверяет имя по сертификату, а не реализует Nginx-сравнение SNI с Host.

Отключение проверки сертификата существует исключительно в явно помеченной
атакующей пробе; нормальные HTTP/3, Xray и Mihomo клиенты проверяют сертификат.
В финальной проверке выбранный TCP-vhost и Hysteria2 используют один отдельный
сертификат с единственным SAN выбранного домена. Строгий SNI отвергает также
имя второго управляемого домена. Эксплуатационный `allowInsecure` не включается.
ALPN остаётся `h3`.
Правильная Hysteria-авторизация получает штатный 233; неправильная не получает
233 и не открывает транспорт. Обычные GET/POST `/auth` обслуживает статический
vhost. Метод авторизации не меняется.

## Нативные экспорты и настоящие клиенты

Важное исправление самого исследования: прежний helper использовал подписку,
полученную **до** записи masquerade. Новый эксперимент получает JSON заново
после запуска нативной панели с кандидатом и после включения строгого SNI.

- Настоящий Xray проверяет исходный нативный JSON через `run -test`.
- В runtime меняются только тестовый адрес/CA, локальный SOCKS-listener и маршрут
  к нему. Экспортированный masquerade сохраняется полностью.
- Серверный UDS временно убирается с экспортированного пути. Клиент стартует
  и передаёт TCP и UDP: следовательно, он не использует этот сокет.
- Проверены три последовательных TCP-передачи и UDP echo 32/512/1200 байт;
  неверный пароль не достигает TCP origin.
- Настоящий Mihomo импортирует неизменённую нативную RAW-подписку, выбирает
  Hysteria2 и передаёт данные с проверкой TLS. Адрес и SNI ссылок соответствуют
  выбранному домену; формат ссылок остаётся штатным.
- После полного перезапуска Nginx сокет создаётся снова, HTTP/3 работает,
  Xray JSON и Mihomo RAW повторно подключаются и передают данные.

Дополнительные серверные поля masquerade содержат только type, URL сокета
и rewriteHost. Сам экспорт, как и раньше, содержит необходимые **клиентские**
credentials; серверные приватные ключи или новый секрет в masquerade не добавлены.
В реализации предлагается фиксированный `/run/3x-ui-hysteria-cover.sock`,
без персональных данных или токенов. Его имя не даёт удалённого доступа к UDS.

## Локальная граница и эксплуатация

Предложен один Nginx-vhost, слушающий только Unix socket и читающий только
существующий document root. В нём нет proxy_pass, панели, API диагностики
или подписок. Неправильный Host отклоняется, autoindex выключен, редиректы
относительные. Доверие IP административного backend не меняется.

Nginx создаёт Unix socket со штатными правами 0666. Это допустимо для этого
**публичного статического** содержимого: каталог `/run` принадлежит root и
не позволяет непривилегированному пользователю подменить имя сокета; локальный
доступ не даёт никаких административных возможностей. Конфигурация остаётся
root:root 0600. После перезагрузки `/run` очищается и сокет создаёт сам Nginx.
Менеджер сокетов, daemon и новый systemd unit не нужны.

Реальный полный reboot с новым backend, обновление сертификата, Change Domains
и полный Restore кандидата: **NOT RUN**, поскольку публичная привязка ещё не
согласована и backend не подключён в установщике. Перезапуски процессов проверены.
Три короткие TCP-передачи занимали примерно 6–15 мс в локальном стенде;
это проверка повторного подключения, а не нагрузочное доказательство отсутствия
регрессии производительности.

## Минимальное изменение и стоимость сопровождения

Предложенный patch показывает ядро решения: один статический vhost, masquerade,
строгий SNI, сертификат существующей REALITY lineage и native Host Hysteria2.
Patch имеет нулевой контекст; проверка применимости:

```bash
git apply --check --unidiff-zero docs/HYSTERIA_REALITY_PROPOSAL.patch
```

**Patch не самодостаточен для установки и не должен применяться к VPS.** Перед
принятием реализации нужны следующие адресные изменения и проверки:

1. `x-ui-latest.sh`: подключить vhost и новый Host/TLS, учесть привязку в извлечении
   managed roles и сертификатном deploy hook. Продление REALITY должно обновлять
   сертификат Hysteria2 без зависимости от продления Panel.
2. `assets/domains/managed.py`: узнавать только старый Panel-вариант и точный новый
   REALITY-вариант; проверять статический vhost, менять его домен вместе с REALITY,
   сохранять старую привязку старых установок, использовать существующий журнал.
3. Backup v3: сохранить нынешние деревья и формат; подтвердить staged-проверку
   нового vhost и REALITY TLS, scoped Certbot ownership, Restore/rollback.
   Изменять валидатор только при выявленной необходимости. Runtime socket в
   архив не включается; его создаёт Nginx.
4. Адресные native/Fresh тесты доменов, сертификатов, старого/нового Restore
   и экспорта; исключение для фиксированного server-only socket в AGENTS/CLAUDE.

У Panel-варианта не меняются Host/TLS и сертификатный hook, поэтому он дешевле.
Но остаётся легко проверяемое расхождение публичного `/assets` по TCP и UDP.
У REALITY выше качество совпадения, ценой небольшой, но реальной смены контракта
Hysteria2. Нет необходимости в форке 3x-ui, переписывателе подписок, новых службах,
копиях сайта или новой системе восстановления. Это ограниченное расширение
существующих управляемых форматов, не поддержка произвольных старых состояний.

## Обнаруживаемость

| Способ | Что меняется в предложенном варианте |
| --- | --- |
| Активное HTTP/3-зондирование | Статический Nginx вместо Go FileServer/пустого ответа Hysteria2; обычные методы, ошибки и заголовки |
| Сопоставление TCP/UDP | На REALITY один домен и один сайт, совпадающие ресурсы и метаданные; известные подписки остаются только по TCP |
| QUIC/TLS fingerprints | Реализация Xray/QUIC и параметры транспорта не имитируются и не скрываются |
| Поведение трафика | Авторизованный транспорт остаётся Hysteria2; статистическая неотличимость не измерялась |
| Блокировки IP/SNI/UDP 443 | Прикрытие не предотвращает такие блокировки |

## Воспроизведение

В одноразовом **nonroot** Ubuntu-контейнере с зависимостями integration suite
из CONTRIBUTING.md установить test-only пакет `python3-aioquic`. Не запускать
на установленном VPS. Нужны свободные TCP/UDP 443 внутри контейнера:

```bash
HY_EXPERIMENT_MODES=unix-comparison NGINX_BIN=/usr/sbin/nginx \
  PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=tests python3 tests/hysteria_cover_probe.py
```

Старые экспериментальные режимы сохранены для воспроизводимости исторического
сравнения и повторно без причины не запускаются. Вывод содержит только метаданные
ответов и результаты проверок, без credentials, содержимого подписок, ключей,
тел ответов и приватных логов. Дополнительной CI-матрицы нет.
